# Команды, сборка и публикация

Основные команды — в CLAUDE.md («Команды»), запуск тестов и чтение их вывода — в навыке `tests`.

**Файловые приложения C#** (`dotnet путь.cs`, `dotnet run -`) — замеры на SDK 10.0.401:

- `#:property PublishAot=false` — в каждом скрипте, включая `dotnet run -`. Без него рефлексия (`JsonSerializer` без генератора) в `tools/` роняет сборку ошибками IL2026/IL3050 — туда доходит `TreatWarningsAsErrors` из `Directory.Build.props`, — а вне репозитория собирается и падает уже при запуске: «Reflection-based serialization has been disabled».
- С `#:include` первая строка — `#!/usr/bin/env dotnet`, иначе CA2266.
- `#:project` на `Finance.Application` делает каждый запуск втрое дольше: MSBuild каждый раз сверяет ссылку. Для часто зовущихся скриптов — `#:package` с той же версией, что в проекте.
- `#:sdk Microsoft.NET.Sdk.Web` запускает скрипт в его собственной папке: относительный путь `docs/ui` ищется в `tools/`. Лечится `#:property RunWorkingDirectory=$(MSBuildStartupDirectory)`. Обычный SDK работает в папке запуска.
- Первый запуск после правки собирает скрипт, дальше он запускается почти мгновенно; кэш — в `%TEMP%\dotnet\runfile`, в папке скрипта `bin` и `obj` не появляются. `dotnet build путь.cs` проверяет компиляцию без запуска.

Сборщик прототипа на Python: на Windows команда называется `python`, `python3` там — заглушка Microsoft Store.

Запись файла через heredoc (`cat > файл <<EOF`) запрещена: в Git Bash на Windows кириллица и кавычки ломают разбор, а кодировка зависит от кодовой страницы. Новый файл пишется целиком, существующий правится точечной заменой. **Массовая правка нескольких мест сразу — C#-скрипт, записанный инструментом Write во временную папку сессии и запущенный `dotnet путь.cs -- аргументы`.** Кириллица в искомых строках и в выводе проходит без настроек (проверено из Git Bash); скрипт вне репозитория не подхватывает его `Directory.Build.props`, и предупреждения не роняют сборку. Первой строкой — `#:property PublishAot=false`, см. выше. Где правка в одном-двух местах — инструмент Edit, а не скрипт.

Скрипт, идущий по существующим файлам, читает и пишет их байтами: метка BOM определяется по первым трём байтам и возвращается на место, а конец строки берётся из самого файла (`text.Contains("\r\n") ? "\r\n" : "\n"`). **Перевод строки в рабочем дереве разный:** большинство файлов лежит с CRLF (`core.autocrlf=true`), часть — с LF (`git ls-files --eol`). Шаблон с одним видом перевода не найдётся в файле с другим, и правка выглядит как «шаблон не найден». Запись с `\n` поверх файла с CRLF переписывает его целиком: правка на две строки приходит в отличиях как файл, изменённый весь.

**Write поверх существующего файла снимает BOM и переводит CRLF в LF** — в отличиях файл выглядит переписанным целиком. Edit их сохраняет. После Write проверь файл `file путь` и верни кодировку скриптом, который читает файл байтами (см. выше).

**Неразрывный пробел в исходниках** (`MoneyFormat.Display` — между суммой и знаком валюты) выглядит обычным: Edit не находит строку с ним — правь по соседнему фрагменту; ` `, набранный в Edit, ложится в файл самим знаком. Увидеть его — `grep … | cat -A` (`M-BM- `).

**Скрипт массовой правки пишется идемпотентным:** `if (count == 0 && text.Contains(replacement)) continue;`. Он почти наверняка упадёт на середине списка — шаблон в очередном файле окажется другим, — а записанные до падения файлы останутся правлеными, и повторный запуск сообщит о них «0 matches». Без этой строки после каждой поправки приходится вручную вырезать из скрипта уже сделанное.

**Удаление куска инструментом Edit с пустой заменой склеивает соседние строки,** если перевод строки не вошёл в удаляемое ровно с одной стороны. После удаления — поиск по месту склейки: сборка и тесты двух инструкций или двух пунктов списка в одной строке не замечают.

`git add` и `git commit` печатают по строке `LF will be replaced by CRLF` на каждый файл (`core.autocrlf=true`, `.gitattributes` нет): полсотни строк шума вместо результата. Из PowerShell хвост фильтруется `| Select-String -NotMatch "LF will be"`.

Многострочное сообщение коммита пишется **из PowerShell** here-string `@'…'@`, закрывающая метка — в нулевой колонке, и передаётся ключом `-m`: `git commit -m @'…'@`. Та же конструкция в Bash уедет в сообщение буквально: заголовком станет `@`, а правка задним числом потребует принудительной отправки. `git commit -F - @'…'@` не работает: PowerShell отдаёт строку аргументом, а не на вход, и git ищет файл с именем, равным сообщению (`pathspec … did not match`).

**Влить ветку в `master`, не переключая основную папку** (в ней может лежать чужая незакоммиченная работа на другой ветке): `git merge-base --is-ancestor master <ветка>` и затем `git push . <ветка>:master` — это перемотка ссылки, без слияния и без выгрузки файлов. Если `master` ушёл вперёд, перемотка откажет: `master` сначала вливается в ветку слиянием (`git merge master --no-edit` в её папке), затем полный `dotnet test` и перемотка — `git rebase` закрыт правами. Ветку, выгруженную в какой-либо папке, так не сдвинуть: git откажет.

**Ловушки сборки.**

- Решение — `Finance.slnx`, не `.sln`: `dotnet sln Finance.sln add` молча не находит файл.
- `dotnet build` принимает ровно один проект: два пути подряд дают `MSB1008`. Для нескольких — по решению целиком.
- `TreatWarningsAsErrors` включён. Чаще всего ломают `CS1573` (описан `<param>` не у всех параметров — описывай либо все, либо ни одного) и `CS1718` (сравнение переменной с самой собой в тесте). `CS1591` (публичный член без `///`) роняет сборку только в `Finance.Domain`, `Finance.Application` и `Finance.Import`: файл документации включён у всех проектов, а в остальных `CS1591` заглушён по имени проекта. В тестах и `Finance.App` то же правило действует, но компилятор его не проверит. Вид комментария (теги в одну строку, `<summary>` в три) сверяет `DocCommentTests`.
- **Лишний `using` роняет сборку** — IDE0005 предупреждением в `.editorconfig`. Без файла документации сборка это правило молча не выдаёт, поэтому файл включён и там, где `CS1591` заглушён. Миграция EF изредка приходит с лишним `using System;` — его снимают руками.
- **`using` под `#if DEBUG`.** Пространство имён, нужное только отладочному коду (`Microsoft.Extensions.Logging` для `AddDebug` в `MauiProgram`), в Release лишнее, и IDE0005 роняет сборку. Debug и тесты этого не видят — `using` оборачивается тем же `#if DEBUG`.
- **`dotnet format` для лишних `using` не годится:** класс `UiTexts` собирается из `.resx` при сборке, `format` его не видит и снимает `using Finance.Application.Texts` там, где он нужен, — в полусотне файлов разом. Лишний `using` убирается по сообщению сборки, руками.
- `Finance.App` собирается только под `net10.0-android`. Папки `Platforms/iOS`, `MacCatalyst`, `Windows` удалены намеренно — приложение только для Android; шаблон MAUI создаёт их заново, восстанавливать не надо.
- В `Finance.App` короткое имя `Application` значит пространство имён `Finance.Application`, а не тип MAUI: вложенное пространство имён побеждает и `using`, и одноимённый псевдоним. Тип MAUI подключён псевдонимом `ControlsApplication` в `GlobalUsings.cs`.
- Найти, что делает MAUI внутри, можно по символам сборки: `strings` в Git Bash нет, зато `grep -ao "ИмяМетода[A-Za-z]*"` по `~/.nuget/packages/microsoft.maui.controls.core/<версия>/lib/net10.0-android36.0/Microsoft.Maui.Controls.dll` перечисляет имена методов — они лежат в сборке обычным текстом.

- **Правка `appiconfg.svg` (`ForegroundFile` у `MauiIcon`) не пересобирает значок:** Resizetizer сверяет дату только основного файла, и в пакет молча уходит прежний передний слой. После правки — удалить `src/Finance.App/obj/<Конфигурация>/net10.0-android/resizetizer/r` (или тронуть `appicon.svg`) и сверить дату `mipmap-xxxhdpi/appicon_foreground.png`. Заставку (`splash.svg`) он пересобирает сам.
- **SVG значков рисует Svg.Skia, а не браузер.** Размытие, градиенты, прозрачность и `clipPath` он умеет, но габарит фигуры считает без выпуклости дуг: фильтр с областью в долях габарита (`x="-30%"`) режет свечение ровной вертикалью. Область фильтра — `filterUnits="userSpaceOnUse"` на весь холст. Смотреть надо на отрисовку из `obj/…/resizetizer`, а не из Chrome: там дефекта нет.

- **`dotnet build Finance.slnx` и `dotnet test` параллельно не запускаются:** они пишут в общие `obj`, и одна из команд падает с `CS2012` (файл занят `VBCSCompiler`). Фоном гоняется одна из них, а не обе.

- **`dotnet test` не собирает `Finance.App`** — только остальные проекты решения. Ошибку компиляции страницы поймает лишь `dotnet build Finance.slnx` (в десятки раз дольше тестов — запускается в фоне). После переезда типа между пространствами имён нужны оба прогона: страницы MAUI видит только сборка решения, а тесты домена лежат в потомке пространства имён `Finance.Domain` и находят доменные типы без `using`, пока те не переедут.

- **`grep -rn` печатает имя файла перед строкой, а в этом репозитории каждый путь содержит `Finance`.** Отсев по содержимому (`| grep -v "Finance.Domain"`) выбрасывает заодно все строки любого файла из `src/Finance.Domain`, и поиск молча возвращает пустоту. Имя файла отрезается до отсева: `| sed 's/^[^:]*:[0-9]*://'`.
- **`grep -P` в этом Git Bash не работает вовсе** — «supports only unibyte and UTF-8 locales», и `LC_ALL=C` не помогает. Ретроспективная проверка (`(?<!Finance\.)`) недоступна и в инструменте Grep: ripgrep отвергает её разбором. Ищется без неё, лишнее отсеивается вторым проходом.
- **Редактор помечает `using Finance.Application.Texts` и каждое `UiTexts.*` ошибкой (CS0234, CS0103) — это ложная тревога.** Класс собирается из `.resx` в `obj` во время сборки, и редактор его не видит. Верить нужно `dotnet build`, а не подсветке.
- **`const` не принимает значение из ресурса** — `CS0133`: свойство сгенерированного класса вычисляется в рантайме. Константа, которой досталась строка интерфейса, переписывается в `private static string X => UiTexts.Key`.
- **`InvariantGlobalization` включать нельзя никогда.** На нём умирают `d MMMM`, `ru-RU` и разбор часовых поясов, а сборка об этом молчит. Запрет продублирован комментарием в `Directory.Build.props` рядом с `NeutralLanguage`.
- **Временно отключить код `if (false)` нельзя:** `CS0162` (недостижимый код) при `TreatWarningsAsErrors` роняет сборку. Когда сверку ломают нарочно, кусок закомментировывается `/* */` или правится сама строка.

Релизная сборка, миграции и публикация:

```
dotnet build -c Release                                      # проверять именно на релизной сборке
dotnet ef migrations add Имя -p src/Finance.Application -s src/Finance.Application -o Infrastructure/Storage/Migrations
dotnet publish src/Finance.App/Finance.App.csproj -f net10.0-android -c Release -p:AndroidPackageFormat=apk -r android-x64 -o apk-builds/<версия>+<хеш>   # для эмулятора: x64 и отладочная подпись; для телефона — команда ниже
```

**Каждая публикация уходит в свою папку `apk-builds/<версия>+<хеш>/`.** Общая папка не годится: `publish` перед собой ничего не чистит, и остатки прошлого запуска лежат вперемешку со свежими — `.aab` пятичасовой давности рядом с сегодняшним `.apk` выглядит частью той же сборки. Хранятся три последние папки, остальные удаляются: каждая весит много, а восстанавливается одной командой. Папка отсечена в `.gitignore` отдельной строкой — правило `artifacts/` её не ловит.

**Версия приложения растёт с каждой выкладкой на телефон.** `ApplicationDisplayVersion` — `1.0.x`, `ApplicationVersion` — это `versionCode` Android и считается из версии как `major*10000 + minor*100 + patch` (минор и патч не больше 99 — релиз это проверяет); на меньший `versionCode` платформа обновление не ставит. Релиз получает оба числа из тега `v1.0.x` и передаёт в командной строке: заданное через `-p:` свойство у MSBuild глобальное и значение из проекта перекрывает. Число в `Finance.App.csproj` поэтому отстаёт от релизов, и это не ошибка — в проекте его не правят. **Сборка для телефона с рабочей машины задаёт версию сама** — `-p:ApplicationDisplayVersion=… -p:ApplicationVersion=…` выше последнего тега (`git tag`): с числом из проекта она поверх релизной не встанет. Экран «О программе» показывает версию из манифеста, так что без роста номера все сборки на устройстве неотличимы.

**Сборка для телефона — только под arm64 (`-r android-arm64`).** Без ключа в пакет ложатся и arm64, и x64 для эмулятора, а с полным AOT это вдвое больше: такой архив не пролезает в канал чата. Эмулятор этой машины — x64, и arm64-пакет на нём не встанет: для проверки на эмуляторе публикуется с `-r android-x64` — одна архитектура вместо двух, и полный AOT идёт около минуты (6 октября 2026). Архитектуру задаёт только `-r`: `-p:RuntimeIdentifiers=android-arm64` — глобальное свойство, оно доходит до библиотек, и их сборка падает с `MSB3030` («не удалось скопировать Finance.Domain.dll»). Состав пакета сверяется `aapt2 dump badging` из `build-tools` SDK — строки `native-code` и `versionCode`.

На телефон ставится только `ru.finance.tracker-Signed.apk`: соседний `ru.finance.tracker.apk` без подписи, Android отвергает его как повреждённый. `.aab` в папке — остаток из `bin` от прошлой публикации без `AndroidPackageFormat=apk`, с прежней датой: это формат загрузки в Google Play, а не пакет установки, и его удаляют сразу.

**Сборка для телефона подписывается своим ключом, а не отладочным из SDK.** Обновление поверх встаёт только с той же подписью: сборка с другим ключом требует удалить приложение вместе с базой — а с ней и всю историю, потому что обмена нет и база единственный источник правды. Ключ и пароль лежат у пользователя вне репозитория, в `%USERPROFILE%\.android-keys\`: `finance-release.keystore` (алиас `finance`) и `pass.txt` с паролем — одна строка ASCII без перевода строки. Пароль в команду не пишется и не печатается: он читается из файла в переменную окружения той же команды, а сборка берёт его приставкой `env:`:

```
$k = "$env:USERPROFILE\.android-keys"
$env:FINANCE_KEY_PASS = [IO.File]::ReadAllText("$k\pass.txt")
dotnet publish src/Finance.App/Finance.App.csproj -f net10.0-android -c Release -r android-arm64 -p:AndroidPackageFormat=apk `
  -p:AndroidKeyStore=true "-p:AndroidSigningKeyStore=$k\finance-release.keystore" -p:AndroidSigningKeyAlias=finance `
  -p:AndroidSigningStorePass=env:FINANCE_KEY_PASS -p:AndroidSigningKeyPass=env:FINANCE_KEY_PASS -o apk-builds/<версия>+<хеш>
```

**Приставка `file:` с одним файлом на оба пароля не работает.** `apksigner`, получив один файл и для хранилища, и для ключа, читает их из него по очереди, строка за строкой: пароль ключа ищется во второй строке, её нет, и подпись падает с «end of file reached». Сборка сообщает об этом одной строкой `MSB6006: "java.exe" завершилась с кодом 2`, а в папке всё равно лежит `-Signed.apk` — без подписи. Опустить пароль ключа нельзя: MSBuild требует его (`XA4314`). У хранилища PKCS12 он совпадает с паролем хранилища, поэтому обе приставки смотрят в одну переменную. **После упавшей подписи повторная публикация её пропускает:** неподписанный `-Signed.apk` в `src/Finance.App/bin/Release` сборка считает свежим и молча копирует его в новую папку с кодом выхода 0. Перед повтором эти файлы удаляются, а результат проверяется `apksigner verify`, а не кодом выхода.

**Прерванная публикация ломает следующую:** `XAGNM7009 … missing native code generation state for architecture 'Arm64'` — остатки в `src/Finance.App/obj/Release`. Лечится удалением `src/Finance.App/obj/Release` и `bin/Release` и повтором.

**Релиз собирает GitHub Actions по тегу** (`.github/workflows/release.yml`): `git tag vX.Y.Z` и `git push origin vX.Y.Z` — только по просьбе пользователя, это выкладка наружу. Из тега выводятся версия и `versionCode`, значения в `Finance.App.csproj` для релиза не правятся. Первыми, до установки MAUI, проверяются секреты, формат тега и то, что он старше прошлого релиза и стоит на `master` (у ручного запуска — только секреты и формат версии). Дальше — тесты в Release, публикация arm64, сверка сертификата пакета с отпечатком ключа пользователя и `FinanceTracker-<версия>.apk` с `.sha256` в релизе; список изменений — заголовки коммитов с прошлого тега. Повторный прогон тега заменяет файлы релиза. Ручной запуск (Actions → Release → Run workflow, ввод — версия) — пробная сборка без релиза: пакет остаётся в артефактах прогона. Ключ — из секретов `ANDROID_KEYSTORE_BASE64` и `ANDROID_KEY_PASS`; их задаёт пользователь, у агента доступа к ним нет.

**Версия набора рабочих нагрузок одна на всё — `workloadVersion` в `global.json`** (сейчас `10.0.400.1`): по ней собирают и рабочая машина, и GitHub, от неё зависят версии MAUI и Android для .NET. Обновление MAUI — правка этого числа; оно привязано к полосе SDK (`10.0.4xx`), и новая полоса требует нового набора. Подготовка сборки общая для релиза и проверки — `.github/actions/setup-android`. Проверка (`.github/workflows/ci.yml`) — только ручной запуск (причина — в шапке файла), поэтому перед push `dotnet test` и `dotnet build Finance.slnx` гоняются локально. Действия GitHub обновляет dependabot (`.github/dependabot.yml`): предложения раз в неделю с префиксом `ci`; MAUI и NuGet он не трогает.

Без этих свойств публикация молча подпишет пакет отладочным ключом — сборка пройдёт, а телефон её поверх не поставит. Чей ключ стоит, сверяет `apksigner verify --print-certs` из `build-tools` SDK: у отладочного в имени владельца `Android Debug`. Сборки для эмулятора подписываются как раньше — отладочным ключом, на телефон они не идут. Потерянный ключ не восстанавливается ничем, поэтому его копия и пароль живут у пользователя ещё и вне этой машины.

**Релиз компилируется полным AOT** (`AndroidEnableProfiledAot=false` в `Finance.App.csproj`): холодный старт заметно короче, а APK тяжелее и публикация дольше. Возвращать профильный AOT «ради размера» не надо — замер и цена записаны комментарием рядом со свойством. Debug собирается без AOT вовсе (как мерить запуск — навык `emulator`). Почему не NativeAOT — там же и в `docs/architecture.md`.

В сгенерированной миграции `descending: new bool[0]` — это **все колонки `DESC`**, а не «ни одной»: пустой массив у EF значит «единообразно по убыванию». Частичный порядок пишется явным списком, как `new[] { false, true, true, true }` у индексов ленты счёта. Сверять стоит по SQL: `dotnet ef migrations script <ПредыдущаяМиграция>`.

Предкомпилированной модели EF нет и не будет, пока у таблиц стоит глобальный фильтр мягкого удаления: `dotnet ef dbcontext optimize` с ним падает, а фильтр важнее.
