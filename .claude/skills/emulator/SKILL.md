# Проверка в эмуляторе

**Правка, которую видно в интерфейсе, проверяется в эмуляторе, а не одними тестами.** `dotnet test` не поднимает ни одной страницы: привязка к `static`-свойству, незарегистрированный обработчик контрола, маршрут поверх имени вкладки, кнопка, уехавшая с экрана вместе со скрытой панелью, — всё это собирается без единого предупреждения и обнаруживается только на устройстве. Тронул слайс `Features/*`, страницу или разметку — открой этот экран и пройди сценарий целиком: заведение, правку, удаление и нарушенное правило.

**Порядок проверки:** логику модели представления — тестом (секунды, без эмулятора), разметку — `dotnet build Finance.slnx`, сценарий — помощником ниже, вёрстку (наехал ли текст, сошлись ли цвета) — снимком. Снимок на порядок дороже экрана текстом и остаётся в переписке до конца сессии.

## Помощник `tools/ui.cs`

Команды идут цепочкой в одном запуске и выполняются по порядку; первая неудача обрывает цепочку строкой «ОШИБКА: …», а промах цели (раздел «Цель» ниже) добавляет к ней экран. Состояние между запусками не живёт: `same` сверяется с `edges` той же цепочки. Сам помощник запускается почти мгновенно, время уходит на `adb`: выгрузка экрана — самая дорогая команда цепочки, лишних `dump` не нужно.

```
dotnet tools/ui.cs -- boot <avd>               # именно этот AVD (чужой гасится), анимации выкл., пояс машины
dotnet tools/ui.cs -- run dump                 # развернуть, дождаться окна, показать экран
dotnet tools/ui.cs -- tap AddTransaction wait SaveTransaction tap 1 tap 2 dump
dotnet tools/ui.cs -- tap SaveTransaction gone SaveTransaction db "select amount, kind from transactions"
dotnet tools/ui.cs -- crash                    # падения процесса, ошибки рантайма .NET и сбои, перехваченные Guarded (тег Finance)
dotnet tools/ui.cs -- edges tap AddTransaction wait SaveTransaction key back wait AddTransaction same   # края не сдвинулись
dotnet tools/ui.cs -- transit AddTransaction wait SaveTransaction transit back   # переход без чёрной полосы
dotnet tools/ui.cs -- help                     # все команды
```

`run`, `start` и `shortcut` сами чистят журнал перед запуском, поэтому `crash` после них показывает только свежее. `run` долгий — запускай его в фоне, пока читаешь код.

**Эмулятор поднимается только `boot <avd>`, а не своей фоновой командой оболочки.** Помощник запускает его отдельным процессом, и тот переживает и команду, и сессию; эмулятор, запущенный фоновой задачей (`run_in_background`), умирает вместе с ней — следующая сессия начиналась с пустого `adb devices`. Имя обязательно, когда важно, какой эмулятор: без него `boot` оставляет уже запущенный, а если такого нет — поднимает первый из `emulator -list-avds`, и развёртывание молча уходило не на тот. Часовой пояс машины `boot` выставляет сам — после перезапуска эмулятор уезжает в GMT.

**Экран (`dump`) — строка на элемент:** `x,y #AutomationId «подпись» [состояния]`. `*` — нажимаемый, `edit` — поле ввода, `hint «…»` — поле пустое и показывает подсказку, `switch on/off`, `selected`, `focused`, `disabled`, `scroll`. Строка списка MAUI — пустой нажимаемый контейнер с надписями внутри; помощник собирает надписи в подпись строки через ` · ` («Еда · 6»).

**Цель (`tap`, `tap2`, `hold`, `transit`, `wait`, `gone`)** ищется по убыванию строгости: `AutomationId` (он приходит в выгрузку как `resource-id`), точная подпись или её часть между ` · `, вхождение без учёта регистра. Координаты `x,y` принимают только `tap`, `tap2`, `hold` и `transit` — без выгрузки экрана; `wait` и `gone` искали бы их как подпись. Из одинаковых точных подписей (вкладка и заголовок «Балансы») берётся нажимаемый узел, неоднозначное вхождение — ошибка со списком кандидатов, а не первое попавшееся: нажатие в соседнюю строку хуже отказа. **Надёжнее всего `AutomationId`:** подпись меняется с текстом в ресурсах. Кнопке, по которой проверяют сценарий, стоит завести `AutomationId` в той же правке. Координаты, пересчитанные со снимка, — последнее средство: пересчёт масштаба — источник промахов по соседней строке, а в тесном режиме (`wm density 460`) координаты другие, и цепочка, записанная числами, ломается. Поля формы операции — лэйауты без `AutomationId` в выгрузке — нажимаются подписью: `tap Категория`, `tap Счёт`, `tap Заметка`; касание подписи доходит до жеста поля.
**`wait` вместо паузы.** Холодный старт занимает секунды (отладочной сборки — заметно дольше релизной), после `-t:Run` окно появляется ещё позже; нажатие, посланное раньше, уходит в заставку молча. `wait цель` опрашивает экран до 20 с, `gone цель` ждёт ухода (сохранение закрыло форму). Помни, что `wait` по подписи срабатывает и на ту же подпись на прежнем экране — ждать лучше `AutomationId` нового экрана.

**`db "select …"`** копирует базу приложения через `run-as` и выполняет запрос на машине. Свежие записи лежат в журнале WAL, а не в самом файле: основной `finance.db` может весить одну страницу при сотнях строк в `-wal`. Помощник копирует все три файла; копия только `finance.db` дала бы пустую базу. Утилиты `sqlite3` на образе нет. Имена колонок — из схемы: `pragma table_info(accounts)`.

**Ограничения, о которых молчит экран:**

- Кириллицу `input text` не передаёт — `text` откажет сразу. Названия для проверки набираются латиницей, доменных правил это не касается. Пробелы `text` набирает сам (`text "two words"`) — подчёркивания вместо них не нужны. Нажать по кириллической подписи можно: поиск идёт по выгрузке.
- Состояние сегментов вида операции («Расход / Доход / Перевод») в выгрузке не видно: `RadioButton` со своим шаблоном не сообщает `checked`. Какой вид выбран, проверяется по базе или снимком.
- **Всплывающее сообщение (`Notice`, системный `Toast`) в выгрузку не попадает:** его рисует система, а не окно приложения. Проверяется снимком в той же цепочке, но не сразу: сообщение появляется с задержкой, и `shot` вплотную за `tap` снимает экран без него. Между ними — `wait` по элементу, который уже на экране (около двух секунд), а живёт сообщение три-четыре. Что оно вообще показалось, подтверждает журнал: `adb logcat -d | grep -i toast`.
- **`AutomationId` у `Grid` и других лэйаутов в выгрузку не попадает** — только у контролов (`Button`, `Entry`, `Label`). По строке-лэйауту нажимают её подписью.
- **Телефон пользователя — самый тесный случай:** `cmd overlay enable com.android.internal.systemui.navbar.threebutton`, `wm density 460`, `settings put system font_scale 1.3`. Возврат: `overlay disable …`, `wm density reset`, `font_scale 1.0`. Проверка «влезает ли над клавиатурой» — только так.
- `key` после нажатия ждёт полсекунды: уход клавиатуры по `key hide` перекладывает страницу, и прокрутка, посланная сразу, теряется.
- **`swipe` помощника при открытой клавиатуре ничего не прокручивает:** жест начинается в нижней половине экрана, то есть на самой клавиатуре. Выглядит ровно как «форма не прокручивается до кнопки» — так чуть не записали в баг рабочую форму. С клавиатурой листают жестом внутри формы: `adb shell input swipe 540 1300 540 400 300`.
- **Тестовые данные в обход приложения обязаны соблюдать доменные правила.** Операции, залитые в базу раньше даты открытия счёта, календарь формы молча подтягивает к дате открытия (`MinimumDate`), и любая правка суммы переписывает дату — выглядит повреждением данных, а это артефакт заливки.

## Жалоба с телефона

Воспроизводится в условиях телефона, а не эмулятора по умолчанию: три кнопки навигации, **включённые анимации** (`boot` их выключает, и мигание на переходе исчезает вовсе) и релизная сборка, если на отладочной не повторилось. Найденный дефект — повод пройти его класс по всем экранам (раздел ниже), а не только названный экран: сдвиг кнопки нашёлся ещё на одном пути к форме, о котором жалобы не было. Сообщение об ошибке, не повторившееся за пару заходов, — сразу просить снимок окна: заголовок `Guarded` отличает сбой действия от сбоя перечитывания, и искать вслепую не придётся.

**Первый запуск — только на отдельном чистом AVD.** На эмуляторе с данными форма сама подставляет счёт, и дефекты «счетов ещё нет» не видны вовсе; стирать его данные ради проверки нельзя. Чистый AVD заводится `avdmanager create avd` на том же образе, что и основной, и выходит на английском — язык системы переключается в «Настройки → Языки» (ключ запуска `-change-locale` на образе с Play Store не действует), часовой пояс `boot` выставляет сам. Чистый поднимается по имени — `boot <имя чистого>`, основной гасится. В списке `emulator -list-avds` имя чистого обязано идти после основного, иначе `boot` без имени на выключенном эмуляторе молча поднимет пустое приложение. Сразу после запуска эмулятора `boot` иногда падает с «no devices/emulators found» — эмулятор ещё не появился в `adb`; повторный `boot` через десяток секунд дожидается загрузки.

## Проверка вёрстки по классам дефектов

Правка каркаса, навигации, safe area, темы или `MainActivity` проверяется не одним экраном, а обходом по классам — каждый ловится своим замером, и ни один не виден в `dump`:

- **Устаревший отступ снизу после возврата с экрана без панели вкладок** (форма операции, экраны выбора). Путей к форме четыре: балансы, лента счёта, «Операции» (кнопкой и строкой), подкатегория отчёта. `edges tap AddTransaction wait SaveTransaction key back wait AddTransaction same` — `same` падает, если края прокрутки или кнопок сдвинулись.
- **Чёрная полоса под строкой состояния на переходе.** `transit <цель|back>` замедляет анимацию вдесятеро, снимает кадры и падает на чёрной полосе. Проходить вперёд и назад на каждом уровне: вкладки, лента счёта, форма, экраны выбора, отчёт → группа → подкатегория, «Ещё» → справочники и карточки. В обеих темах: в тёмной полоса цветом шапки (28,33,36), а не чёрная.
- **Формы с системной клавиатурой** (счёт, группа, подкатегория, место, заметка операции): с клавиатурой страница ужимается над ней, и «Сохранить» докручивается жестом внутри формы; после `key hide` края возвращаются к прежним (`edges` до и `same` после, в одной цепочке).
- **Тема со страницами в стеке:** сменить тему в «Оформлении» и пройти вкладки — созданные раньше страницы, строка состояния и панель системных кнопок перекрашены.
- **Тесный режим телефона** (три кнопки, `wm density 460`, `font_scale 1.3`): тот же обход плюс снимок формы — клавиатура суммы и «Сохранить» на экране, полоса системных кнопок цветом приложения, а не светлая.

С тремя кнопками экран короче, и «Сохранить» у карточки группы уходит ниже прокрутки: `wait SaveGroup` там падает без дефекта — перед ним `swipe up`. Обход занимает минуты: цепочки режутся так, чтобы каждая укладывалась в десять минут ожидания команды, иначе прерванный `transit` оставил бы эмулятор с замедленной анимацией.

## Ловушки устройства

- **После `adb uninstall` счетов нет: на «Балансах» нет `AddTransaction`, ждать `CreateFirstAccount`.** Цепочка с `wait AddTransaction` на чистой установке падает по таймауту без всякого дефекта.

- **Включённая защита входа ставит заслонку на каждый `run`, `start` и `shortcut`**, и `wait AddTransaction` падает по таймауту. Вход — касаниями клавиш: `wait PinTitle tap Pin1 tap Pin3 …`. Закончив проверку, защиту выключают («Ещё → Защита входа → Выключить защиту»): следующая сессия о ней не знает. Пауза после неверных попыток переживает и перезапуск, и `run`; снимает её только `adb uninstall`. Пять минут фона без ожидания не проверить — ждут фоновой командой `sleep 315`, а не `wait`.
- **С включёнными анимациями экран с атмосферой (`Backdrop`: заслонка, экран ПИН-кода) не выгружается:** пятна плывут непрерывно, и `uiautomator` падает с «could not get idle state» — `dump`, `wait` и `tap` по подписи там не работают. `boot` анимации выключает, и пятна стоят. Анимации заслонки смотрят с включёнными (`settings put global window_animation_scale 1`, так же `transition_animation_scale` и `animator_duration_scale`), касаясь координатами и снимая `shot`; на Pixel 7 без масштаба клавиши заслонки — столбцы 262, 540, 818, ряды 1134, 1386, 1638, 1890 (ноль — 540,1890).

- **`wait 2000` — не пауза:** помощник ищет на экране подпись «2000» и через 20 с падает. Пауза — `wait` по элементу, который уже на экране.
- **Сразу после системного окна (выбор файла, «Поделиться», перезапуск) `dump` бывает пустым** — «null root node returned by UiTestAutomationBridge». Это не сбой приложения: повторный `dump` или `wait` через секунду проходит.
- **Первый запуск сразу после установки (релизной и отладочной сборки) показывает «не отвечает»** и поднимается по «Подождать» — в цепочке `tap aerr_wait`; следующие холодные старты проходят без этого. Не регрессия.
- **«Окно приложения не появилось» после `run` при пустом `crash`** — не падение: отладочная сборка после свежей установки стартует дольше ожидания помощника. Следующий `start` открывает её за секунды.
- **Холодный старт проверяется только после force-stop** — `start` и `shortcut` делают его сами. Иначе намерение уходит в живое приложение и проверяет совсем другую ветку кода.
- **Часы эмулятора могут отставать и стоять в GMT** — операции «сегодня» по Москве домен отвергнет как будущие. Сверка — `adb shell date`. Пояс: `adb shell service call alarm 3 s16 Europe/Moscow`. Дату `date` не ставит (образ не отладочный, `adb root` запрещён): «Настройки → Дата и время», выключить автоопределение, выбрать день.
- **Системный выбор файла не показывает файл, положенный `adb push`, в «Недавних»:** «Показать корневые папки» → «Скачанные».
- **Ярлыки на значке:** `shortcut Expense|Income|Transfer` открывает приложение ярлыком. Состав ярлыков — `adb shell dumpsys shortcut`. Долгое нажатие на значке — `hold`: дольше секунды лаунчер принимает удержание за перетаскивание значка, 600 мс открывают меню.
- **Смена вида операции — уже правка формы.** Обратный ход после неё показывает «Выйти без сохранения?», и следующее нажатие уходит в диалог, а не на экран под ним. После каждого возврата — `dump`.
- **Двойное нажатие — `tap2`:** два `input tap` одной командой оболочки, между ними около 100 мс. Этого хватает, чтобы первое сохранение завершилось, поэтому защита обязана переживать успех, а не только ожидание.
- **`pm clear` у отладочной сборки стирает и её сборки быстрого развёртывания** (`files/.__override__`): следующий `start` падает с «No assemblies found … Fast Deployment», а `run` их не перезаливает — считает пакет уже стоящим. Вернуть первый запуск — `adb uninstall ru.finance.tracker` и `run`.
- **Падение при старте с «valid TextAppearance attribute» бывает и при правильном `styles.xml`.** Ресурсы Android упаковываются послойно, и `obj`/`bin` проекта `Finance.App`, оставшиеся от состояния до правки стиля, переживают обычную пересборку. Лечится удалением `src/Finance.App/obj` и `src/Finance.App/bin` с полной пересборкой (около минуты). Прежде чем искать ошибку в разметке, проверь это.
- **Культура берётся при старте процесса.** После смены языка устройства нужен `start`: без него даты остаются в прежнем формате, а `Money.Display` — с прежним разделителем.
- **Релизная сборка на эмуляторе закрывает базу:** она не отладочная, и `run-as` отвечает «package not debuggable» — `db` помощника падает с «file is not a database», потому что вместо файла получил текст ошибки.
- **Возврат к отладочной сборке `-t:Install` после релизной молча пропускает установку:** быстрое развёртывание считает пакет уже стоящим. Ставится с `-p:EmbedAssembliesIntoApk=true`, данные поверх сохраняются; при нехватке места такая установка падает (следующий пункт), и тогда ставят `run`.
- **Установка падает с `INSTALL_FAILED_INSUFFICIENT_STORAGE` («Requested internal only, but not enough space»), хотя свободно сотни мегабайт:** система держит запас в 10 % раздела `/data`; снижается он `settings put global sys_storage_threshold_percentage 2`. Ещё около 120 МБ держит кэш быстрого развёртывания отладочной сборки — `run-as ru.finance.tracker` и папка `files/.__override__`; релизной он не нужен, следующий `run` зальёт его заново. Упавшая так установка отладочной сборки может успеть удалить стоявший пакет, но данные приложения переживают, и следующий `run` ставит его заново.
- **Время запуска меряется только на релизной сборке**, медианой десяти холодных стартов после двух прогревочных: `am start -W` печатает `TotalTime`. Первый кадр приходит уже с данными — подготовка базы и первое чтение успевают до отрисовки, так что `TotalTime` и есть время до готового экрана. Эмулятор сравнивает варианты между собой, абсолютные числа на телефоне другие.
- **Снимки (`shot`) кладутся в `artifacts/`** — папка в `.gitignore` (как и `*.png` в корне); снимок в любой другой папке уедет в `git add -A` вместе с правкой. Пакетам место в `apk-builds/`, данным задачи — в папке этой задачи.
- **Запись в `files/` приложения** — `adb exec-in run-as <пакет> sh -c "cat > files/<имя>"`: `cp` из `/data/local/tmp` под `run-as` молча не срабатывает.
- **Подмена базы приложения (залить сотни операций для проверки ленты, вернуть прежнюю):** после `am force-stop` рядом с `finance.db` остаются `-wal` и `-shm` прежней базы, и SQLite накатит чужой журнал поверх нового файла. Вместе с базой они записываются пустыми — `exec-in … sh -c "cat > files/finance.db-wal" < /dev/null`, так же `-shm`, — а залитая копия перед отправкой сводится `pragma wal_checkpoint(TRUNCATE)`. Проверка — `db "pragma integrity_check"`.
- **Данные для проверки на чистом AVD — временным тестом, а не касаниями:** тест на `TransactionFixture` заводит счета и операции, делает `PRAGMA wal_checkpoint(TRUNCATE)` и копирует файл базы в `artifacts/` (путь — переменной окружения, без неё тест молчит). Заливка — как в пункте выше; прежняя база снимается заранее (`exec-out run-as … cat files/finance.db`) и возвращается после проверки. Тест удаляется до коммита. Даты операций — от `TestTime` (15 сентября 2026): на эмуляторе их месяц открывается стрелкой назад.
- **Повторный `run` может оставить на эмуляторе старые сборки**: «развёрнуто за 3 с», а экран прежний. Сверяй по `dump`, что правка видна. На чистом AVD лечится `adb uninstall ru.finance.tracker` и `run`.
- **«UiAutomationService … already registered» в `crash` — это падение самого `uiautomator`, а не приложения.** После него приложение уходит в фон, на экране лаунчер, и `wait` падает по таймауту. Нужен `start`.
- **Тёмная тема без «Оформления»** — при системной теме в приложении: `adb shell cmd uimode night yes`, затем `start`; вернуть — `night no`.

## `adb` напрямую

Помощник покрывает обычный сценарий; для остального — `adb` по полному пути (в PATH его нет): `"/c/Program Files (x86)/Android/android-sdk/platform-tools/adb.exe"`, а если задан `ANDROID_HOME` — `platform-tools/adb.exe` под ним, как берёт помощник.

- **Git Bash переписывает пути устройства в пути Windows:** `/sdcard/ui.xml` уходит в `adb` как `C:/Program Files/Git/sdcard/ui.xml`, команда «проходит», а файла нет. Перед такими командами — `export MSYS_NO_PATHCONV=1`. Помощник этой ловушки не знает: он зовёт `adb` без оболочки.
- **Смахивание строки влево** — `adb shell input swipe 900 <y> 350 <y> 300` (из PowerShell, `& "…\adb.exe"`): у помощника `swipe` только вертикальный. Кнопка под смахнутой строкой нажимается координатами, у `SwipeItemView` нет `AutomationId` в выгрузке.
- **Выделение в ленте — `hold <x,y>` по строке**, снятие — `tap EndSelection` или `key back`. Отметка строки приходит в окно с задержкой: снимок вплотную за касанием показывает счётчик «Выбрано: 2» при одной отмеченной строке — это не ошибка, перед `shot` нужен `wait` по элементу на экране.
- **Развёртывание без помощника:** `dotnet build src/Finance.App/Finance.App.csproj -f net10.0-android -t:Run '-p:AdbTarget=-s emulator-5554'`. Кавычки вокруг `-p:AdbTarget=…` обязательны: без них аргумент рвётся по пробелу, а MSBuild сообщает `XA0010` — «выбранное устройство не запущено», хотя оно работает.
- **`uiautomator dump /dev/tty` дописывает после XML строку** «UI hierchary dumped to: /dev/tty», и разбор XML на ней падает.
