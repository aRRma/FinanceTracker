# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

**Личный трекер финансов** — Android-приложение для персонального учёта финансов. Один пользователь, несколько его устройств (в MVP — одно и без сети). Офлайн-first: источник правды — локальная база. Сервер только обменивает изменения между устройствами и **не содержит доменной логики**.

## Состояние репозитория

**MVP собран целиком и стоит на телефоне с перенесённой историей;** что открыто и что дальше — в [PLAN.md](PLAN.md). Слайсы — в `Finance.Application/Features/*`, страницы и контролы — в `Finance.App`; состав виден по папкам.

Весь текст для пользователя — в ресурсах: `Texts/UiTexts.resx` (и названия значков `Texts/IconNames.resx`) в прикладном слое, `Errors/RuleTexts.resx` в домене. Язык пока один, русский, и приходит параметром `AddFinance`: перевод — по второму файлу к каждому `.resx`, без правок кода.

**Правки в [data/preset.json](data/preset.json) необратимы — откат в git не вернёт выданные идентификаторы:** из ключей и `namespace` выводятся UUIDv5. `namespace` не меняется никогда, ключ категории не получает другого смысла и не переиспользуется; убрать строку можно. Установленной базе правку набора приносит только миграция. `dotnet test` до правки набора и после. Правка тянет за собой числа в `PresetTests` (группы, подкатегории, всего), `presetVersion` в `Испорченный_набор_не_разбирается`, счётчики групп на макетах B-03 и D-03, таблицы и итог `docs/preset-rationale.md`. Ключи новых строк — английские snake_case, у подкатегории `ключ_группы.имя`: исправить их можно только до закрепления набора. Метка `seededAtUtc` — заведомо давняя: текущее время затёрло бы переименования при переустановке ([ADR-0006](docs/adr/0006-preset-deterministic-keys-and-fixed-seed-time.md)).

## Навыки

Подробности вынесены в навыки под `.claude/skills/` и загружаются по требованию. Навык загружается **до** первого действия, а не после ошибки; правило из навыка действует так же, как записанное здесь, и «в контексте этого не было» оправданием не служит.

- **Трогаешь эмулятор — сначала навык `emulator`, потом первая команда `adb` или `tools/ui.cs`.** Помощник проверки, экран текстом, нажатия, база приложения, журнал падений, ярлыки.
- **Собираешь, публикуешь, пишешь миграцию или скрипт массовой правки — сначала навык `build`.** Ловушки MSBuild, кодировок, git и `dotnet ef`.
- **Пишешь тест, правишь запрос к базе или заводишь доменное правило — сначала навык `tests`.** Фикстуры, планы запросов, устройство ленты и отчёта, ловушки EF и проверки документации.
- **Правишь страницу, контрол, разметку или модель представления экрана — сначала навык `maui`.** Общие правила экранов, формы, клавиатура суммы, выбор на отдельных экранах, навигация `Shell`, ловушки XAML.
- **Добавляешь или правишь текст для пользователя, сообщение правила, счётную форму или дату — сначала навык `texts`.** Ресурсы, `RuleText`, ленивые сообщения, подстановки, культура.

**Тихие ловушки** — о них молчат и сборка, и тесты, и экран:

- `dotnet test` не собирает `Finance.App`: ошибку страницы, как и переезд типа между пространствами имён, ловит только `dotnet build Finance.slnx` (навык `build`).
- `InvariantGlobalization` не включать никогда: молча умирают даты, русская культура и часовые пояса (навык `build`).
- Падение на устройстве молчит: окно закрывается, причина — только в журнале, `dotnet tools/ui.cs -- crash` (навык `emulator`).
- Git Bash переписывает пути устройства (`/sdcard/…`) в пути Windows, и `adb` работает не с тем файлом (навык `emulator`).
- Устаревший отступ снизу после возврата с экрана без панели вкладок и чёрная полоса на переходе не видны ни в `dump`, ни при выключенных анимациях: ловят их только `edges`/`same` и `transit` помощника (навык `emulator`).
- `{Binding}` не видит `static`-свойство модели; свой наследник `Shape` без `AddHandler` роняет экран; первый сегмент маршрута не совпадает ни с вкладкой, ни с чужим маршрутом (навык `maui`).
- Сгруппированный `CollectionView` падает, если группу заменить на группу с другим числом строк, и не показывает `EmptyView`, если опустел поштучно (навык `maui`).
- Тест, зависящий от культуры машины, зелёный здесь (ru-RU) и красный в GitHub Actions (en-US): культура закреплена в `TestCulture` (навык `tests`).
- Упавший процесс тестов (переполнение стека) всё равно печатает «Пройден!» — с меньшим числом тестов: сверяй число с прошлым прогоном и лови `прерван` (навык `tests`).
- `dotnet publish` без свойств подписи подписывает пакет отладочным ключом, и поверх установленного он не встанет: сборка для телефона — только командой из навыка `build`.

## Как вести работу

- **Независимые команды — одной пачкой**, по очереди — зависимые, а также `dotnet build` и `dotnet test` (общие `obj`, навык `build`). **Читать узко:** нужный кусок файла, поиск вместо вывода всего.
- **Во время работы гоняется один класс тестов** — ради короткого вывода; полный `dotnet test` идёт секунды и прогоняется в конце правки. Заметно дольше опорного замера из навыка `tests` — ищи причину. Любое падение — регрессия: случайных падений в наборе нет.
- **Долгая сборка и публикация — в фоне**, а пока они идут, читается код или правится документация.
- **Новая проверка ломается нарочно в момент написания** — портят данные, убирают пометку или защиту, — и падает с внятным сообщением; потом возвращается как было. Зелёной она бывает и оттого, что ничего не нашла.
- **Находка субагента перепроверяется по коду или в эмуляторе до правки:** отчёт аудита — список гипотез, а не багов.

## Границы MVP и стек

Одно устройство одного пользователя, **без сети**. Обмен с сервером отложен целиком — сервер, протокол, очередь отправки, слияние правок; поля схемы под него заведены сразу, чтобы не переделывать базу задним числом. `Finance.Contracts` и `Finance.Server` появятся вместе с обменом; `Contracts` не будет ссылаться на `Domain`: сервер не исполняет доменную логику. Отчёт о расходах и доходах по группам за месяц в MVP входит.

C# 14 · .NET 10 · MAUI (Android 16+) · EF Core + SQLite · xUnit. Сервер на ASP.NET Core Minimal API и PostgreSQL — вместе с обменом, вне MVP.

## Проекты

`Finance.Domain` (без зависимостей; папки `Entities`, `Enums`, `Values`, `Rules`, `Errors`) · `Finance.Application` (слайсы функций и инфраструктура папкой внутри) · `Finance.App` (MAUI: только страницы, навигация, ресурсы темы) · `Finance.Import` (перенос из других приложений на рабочей машине; приложение на него не ссылается — сверяет `ProjectReferenceTests`) · `Finance.Domain.Tests` · `Finance.Application.Tests` (на настоящей базе SQLite) · `Finance.Docs.Tests` (стартовый набор, покрытие правил требованиями и тестами, согласованность документации). Устройство слоёв — [docs/architecture.md](docs/architecture.md).

- **Пространство имён совпадает с папкой во всех проектах.** Исключений два: `GlobalUsings.cs` без объявления и `Platforms/Android/*`, где все типы остаются в `Finance.App`. Переезд типа — повод сверить `namespace` каждого файла с его путём. `Invariant` — перечисление, но живёт в `Errors`: это каталог нарушений к `DomainException`.
- **Слайсы режутся по функциям и не ссылаются друг на друга;** запрос или обработчик, понадобившийся второму слайсу, переезжает в общую инфраструктуру.
- **Обработчики и модели представления живут вне MAUI намеренно:** обычная библиотека тестируется обычным xUnit, без эмулятора. В `Finance.App` — только то, что без MAUI не существует.

## Правила, нарушение которых ломает данные молча

Обоснование каждого — в [docs/adr/](docs/adr/) и в «Особенностях реализации» [docs/architecture.md](docs/architecture.md).

- **Идентификаторы — UUIDv7, генерирует клиент** (`ValueGeneratedNever()`), в SQLite — TEXT в каноническом виде: `Guid.ToByteArray()` без `bigEndian: true` переставляет байты и ломает сортировку ленты ([ADR-0002](docs/adr/0002-client-uuidv7-stored-as-text.md)).
- **Деньги — тип `Money` (`decimal` плюс валюта)**, сложение разных валют бросает исключение: общей суммы по валютам не существует ([ADR-0004](docs/adr/0004-money-decimal-currency-in-type-no-conversion.md)). В SQLite — целыми копейками в `INTEGER` через один конвертер: по TEXT не работают ни `SUM`, ни сравнение ([ADR-0011](docs/adr/0011-money-stored-in-minor-units.md)).
- **`Money.Create` считает записанные знаки, а не значение: `1.500` отвергается наравне с `1.505`.** Хвост нулей срезает вызывающий код. `[InlineData("1.500")]` выглядит ошибкой и ею не является.
- **Суммы всегда положительны, знак задаёт `kind`.** Расход отрицательной суммой ушёл бы в баланс дважды в одну сторону.
- **Моменты — UTC, `DateTimeOffset`, суффикс `_at_utc`; календарные даты — `DateOnly`, суффикс `_on`, без конвертаций** ([ADR-0009](docs/adr/0009-calendar-dates-without-time.md)). В SQLite момент — TEXT фиксированной длины с нулевым смещением. «Сегодня» — локальная дата пользователя, не `UtcNow.Date`. Часовой пояс — идентификатор зоны, а не смещение.
- **Удаление мягкое всегда:** физический `DELETE` не даст будущему обмену узнать об удалении ([ADR-0003](docs/adr/0003-sync-fields-and-soft-delete-before-sync.md)). Исключение — строки настроек: они не сущности и в обмен не идут. Удаление места не трогает строки операций: они показываются без места, массовая правка ссылок запрещена.
- **Перед миграцией схемы — резервная копия** через `VACUUM INTO`, при неудаче — откат на неё; копия одна.
- **Восстановление из выгрузки мигрирует присланный файл во временной папке до записи** и пишет в рабочую базу только проверенный файл ([ADR-0015](docs/adr/0015-export-is-database-file.md)): миграция на месте рабочей базы при неудаче оставила бы приложение без данных.
- **Операции счёта — никогда `source = ? OR target = ?`:** лента, баланс и итоги дня счёта считаются по сторонам порознь (`AccountTransactions.BothSides`), у общей ленты свой индекс без счёта; планы запросов сверяются тестами. Устройство ленты, итогов дня и отчёта — навык `tests`.
- **Группа бывает универсальной** (`Category.AcceptsAnyKind`): принимает оба вида, возврат в расходной группе вычитается из её расхода. Флаг задаётся при заведении и не меняется, как и вид. Служебная группа одна и универсальная, ключ `service_exp` ([ADR-0013](docs/adr/0013-universal-groups-refund-nets-against-expense.md)).
- **Переводы и валютные операции в отчёт не входят;** счета, входящие в суммы, — один предикат `CountedAccounts` на итог дня и на отчёт (навык `tests`).
- **Значки категорий — только из [data/icons.json](data/icons.json)**, контуры — в [data/icon-paths.json](data/icon-paths.json), и у каждого ключа набора контур обязан быть. **Цвета — только именованные токены темы**, контраст сверяет `ContrastTests`. Значок счёта — один маппинг `AccountIcon.For` и свой набор `AccountIcon.Choices`, знак счёта — один контрол `AccountBadge`; цвет счёта — восемь токенов `Account{Цвет}`, у них сверяется только значок на заливке, не ниже 3 (навык `maui`).
- **Возврат настройки к системному значению — удаление строки**, а не запись слова «системный»; тема — исключение.

## Стиль C#

Порядок приоритетов: **корректность → читаемость → производительность**. Образец — соглашения .NET, Framework Design Guidelines и анализатор CA18xx. `LangVersion` — `latest` (C# 14): старый синтаксис при наличии нового — повод переписать (collection expressions, `field`, блоки `extension`, `?.=`, raw strings, pattern matching вместо цепочек `if`). Один тип — один файл; file-scoped namespace, `using` вне него, `using var` без скобок; ключевые слова типов (`string`, `int`), `var` — только когда тип виден справа, в `foreach` тип явно; `=>` для методов из одного действия; именованные аргументы, где подряд идут `null`, `true` или `false`; `is` с константой вместо `==` для перечислений; `required`/`init` вместо конструкторов-перечислителей; `Func<>`/`Action<>` вместо своих делегатов; `&&`/`||`, не `&`/`|`; аргументы — `ArgumentNullException.ThrowIfNull` и подобными; голый `catch (Exception)` без фильтра запрещён, повторный выброс — `throw;`.

- **Первый член перечисления — `Unknown = 0`, номера у всех членов явные** — перестановка строк без номеров молча меняет смысл запомненного. Исключение — `[Flags]` с `None = 0`. `Unknown` настоящим значением не бывает, но доменным правилом его не проверяют: `Invariant.Unknown` из сверки покрытия исключён явно. Перечисления хранятся именем, а не номером — в SQLite (`HaveConversion<string>()`) и в наборе.
- **У доменных типов с фабрикой ничто не создаёт значение в обход проверок:** ни первичный конструктор, ни открытый `init`/`required`, ни `with` у `record`. `required`/`init` — для моделей чтения, команд и моделей представления.
- **Бесплатное по читаемости делается всегда:** `sealed` по умолчанию — и у страниц `Finance.App` (база объявляется `abstract`, сверяет `Классы_запечатаны_если_не_задуманы_базой`; миграции EF не в счёт), `readonly struct` (не `readonly record struct` в домене), `FrozenDictionary`/`FrozenSet` для справочников, `SearchValues`, `[GeneratedRegex]`, `Span` и `TryFormat` вместо промежуточных строк, `string.Create` с культурой вместо склейки через `+`, без LINQ во внутренних циклах, `static`-лямбды, `Count`/`Length` вместо `Count()`, `TryGetValue`. **JSON — только генератором `JsonSerializerContext`:** отражение не переживает обрезку кода в релизе.
- **Ввод-вывод — `async` с `CancellationToken` до низа, без `.Result` и `.Wait()`.** `ConfigureAwait(false)` — в домене, прикладном слое и переносе; в модели представления — только там, где после `await` не правятся привязанные свойства; в `Finance.App` — нет.
- **EF Core:** чтение — `AsNoTracking` и проекция `Select` в плоскую модель на стороне базы, без N+1.
- **Оптимизация, ухудшающая читаемость** (`stackalloc`, `ArrayPool`, `Unsafe`, ручные циклы), — только по замеру BenchmarkDotNet или профилировщика и с комментарием о выигрыше.

## Как устроен код

- **Конструкторы доменных типов закрыты:** создание — фабрикой с полной проверкой, восстановление из хранилища — публичным путём без проверок, и его комментарий обязан это говорить.
- **Пишущий путь — через доменные типы, читающий — в плоские модели** с проекцией на стороне базы; доменные сущности между контекстами не передаются. Обработчики зовутся моделями представления напрямую через интерфейсы, без посредника.
- **Межтабличные проверки:** прочитанные данные подаются параметром, решение остаётся за доменом (`TransactionRules`, `CategoryRules`, `NameUniqueness`). В хранилище домен не ходит никогда.
- **Доменные правила названы членами `Invariant`, а не номерами:** `DomainException.Invariant` говорит, какое правило нарушено, и тест сверяется с ним, а не с текстом. Новое правило — четыре правки разом: член `Invariant` с комментарием, строка в [docs/requirements/02-domain.md](docs/requirements/02-domain.md) с `` `Invariant.Имя` `` ровно один раз, проверка в домене и тест с `[Trait]`. Пропуск любой роняет `dotnet test`.
- **Сообщение `DomainException.ThrowIf` собирается только при нарушении:** подстановки — обобщёнными параметрами, интерполированная строка — через `DomainMessage`, а не `string`. Сливать перегрузки нельзя, иначе сообщение собиралось бы на каждую сумму (`Текст_не_собирается_когда_требование_не_нарушено`).
- **Пользователю показывается текст только `DomainException` и `DatabaseMigrationException`;** остальное — общим сообщением и в журнал.
- **Обработчик события в `Finance.App` синхронный и зовёт `Guarded.Run`** — единственное место в `Finance.App`, где `async void` разрешён и перехвачен (в прикладном слое такой один — `ScreenViewModel.OnChanged`, со своим перехватом); асинхронная команда в разметку не привязывается, переход по касанию — `Navigator.Go`. Сверяет `Обработчики_событий_не_объявлены_async_void`.
- **Модель, перечитывающая экран, наследует `ScreenViewModel`,** подписка живёт от появления экрана до ухода, признак модели доводится до разметки в той же правке (навык `maui`).
- **`updated_at_utc` — при сохранении,** в переопределении `SaveChanges`; инициализация базы идёт в обход. **Команда — одна транзакция через `UnitOfWork`,** он же публикует события изменения после фиксации; обработчики друг друга не вызывают.
- **Время — только через `IClock`:** прямой `UtcNow` или `DateTime.Now` в `src/` обходит зону пользователя и тестовые часы (`Время_читается_только_через_часы_приложения`).
- **Строки для пользователя — в ресурсах** (`Русских_строк_в_коде_нет`); **текст — одна короткая мысль без пересказа правил**, пояснение к моменту действия — `Notice.Show` (навык `texts`).
- **Проверять на релизной сборке:** отсечение неиспользуемого кода ломает механизмы на отражении.

## Язык и комментарии

- **Код — только английский;** смешанные имена вида `AddОперация` недопустимы. **Имена — из [CONTEXT.md](CONTEXT.md):** новый термин сначала попадает в словарь, потом в код.
- **Комментарии — на русском:** публичные члены — XML-документацией (`///`), внутри методов — обычными. Все публичные методы и сущности прокомментированы, приватные — где неочевидно почему. **Зачем, а не что:** пересказ сигнатуры устаревает молча.
- **`<summary>` и `<remarks>` — всегда три строки**, даже для одной фразы: иначе дописать второе предложение — переписать строку. `<param>`, `<returns>`, `<exception>`, `<typeparam>` — однострочные, пояснение длиннее строки — в `<remarks>`. Сверяет `DocCommentTests`.

  ```csharp
  /// <summary>
  /// Рубль. Валюта итогов дня и отчёта — единственная, в которой считаются общие суммы.
  /// </summary>
  ```

- **В доменной сущности комментарий описывает инвариант, в слайсе — сценарий,** иначе одно правило записано дважды и разойдётся.
- **Номера требований в код, тесты, этот файл и [PLAN.md](PLAN.md) не переносятся, ADR в коде и тестах — тоже** — правило называется словами или членом `Invariant` (в коде, разметке, csproj и манифесте это сверяет `Номера_требований_не_попадают_в_код`, в остальном — дисциплина). В документах ADR — ссылка на файл рядом с правилом, названным словами; ссылаться на экраны макета (`A-01`) можно.
- **Отменённое решение записывается, а не стирается:** зачёркнутым пунктом в [PLAN.md](PLAN.md) и причиной в правиле — иначе его предложат заново.
- **Замер скорости или размера в правило не пишется** — только соотношением; замер с датой живёт рядом с решением, которое обосновывает.
- **Документация сейчас на русском;** после перевода на английский дополнения пишутся на английском.

## Команды

```
dotnet test                                     # домен, слайсы на SQLite, стартовый набор, покрытие правил, документация
dotnet test tests/Finance.Application.Tests/Finance.Application.Tests.csproj --filter "FullyQualifiedName~ИмяКласса"
dotnet build Finance.slnx                       # только он собирает Finance.App
dotnet tools/coverage.cs [-- ИмяФайла]          # покрытие тестами: итог или непокрытые строки файла
dotnet tools/ui.cs -- boot <avd> run dump       # эмулятор, развёртывание, экран текстом; справка — help
python tools/build_prototype.py                 # после КАЖДОЙ правки mockups.html
dotnet tools/mockup_icons.cs                    # значки макетов из набора приложения — после новой ссылки #i-ключ
git tag vX.Y.Z; git push origin vX.Y.Z          # релиз в GitHub Actions: тесты, подпись, APK в Releases — только по просьбе пользователя
```

**Скрипты и разовые команды — на C#:** файловое приложение .NET 10 в `tools/` или во временной папке сессии (`dotnet путь.cs -- аргументы`), разовое выражение — `echo '…' | dotnet run -`, раздача папки — `dotnet tools/serve.cs -- docs/ui 8777`. Python — только в сборщике прототипа; новый — с согласия пользователя. Ловушки файловых приложений — навык `build`.

**Правка, которую видно в интерфейсе, проверяется в эмуляторе, а не одними тестами:** тронул слайс, страницу или разметку — пройди сценарий целиком через `tools/ui.cs`: заведение, правку, удаление и нарушенное правило.

## Чего не делать

- Не начинать обмен с сервером: поля схемы заведены, кода быть не должно.
- Не вводить второй идентификатор рядом с `key`.
- Не расширять дерево категорий до трёх уровней — вместо этого поле «Место» (`place_key`).
- Не переиспользовать номера аннулированных и отложенных требований: они помечены зачёркнутым заголовком.
- Не реализовывать то, что в [docs/requirements/01-scope.md](docs/requirements/01-scope.md) помечено вне MVP: теги, вложения, будущие и повторяющиеся операции, бюджеты, импорт, поиск и фильтры, экспорт для анализа (таблицы, CSV). Исключения: разовый перенос истории из Wallet (сборка `Finance.Import`, [ADR-0014](docs/adr/0014-wallet-import-one-shot-through-domain-path.md)) — не функция импорта для пользователя; выгрузка базы в файл и восстановление из неё ([ADR-0015](docs/adr/0015-export-is-database-file.md)) — файл читает только само приложение.
- Не класть в репозиторий личные финансовые данные — ни снятые данные, ни сводки: число операций по категориям тоже говорит о человеке. Снятые данные и всё, что из них получено, живут в `artifacts/` внутри задачи (папка в `.gitignore`); в документах такой файл называется обычным текстом, без обратных кавычек.
