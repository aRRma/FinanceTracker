# Как достать данные из Wallet

Инструкция воспроизводимая: по ней выгрузка снимается заново с нуля. Занимает пять минут,
из них четыре — ожидание синхронизации.

## Что сработало и почему именно это

Веб-версия Wallet держит **всю** базу пользователя локально в браузере: это PouchDB поверх
IndexedDB, реплика серверной CouchDB. Не кэш последнего экрана, а полная копия — со всеми
операциями, справочниками и служебными полями. Забирается она обычным чтением IndexedDB
из консоли, без подписки, без прав и без обращений к серверу.

## Шаги

**1. Синхронизировать телефон.** Открыть Wallet на телефоне и дождаться, пока он отдаст
последние операции. Веб-версия реплицируется отдельно, и без этого шага в выгрузке не будет
нескольких последних дней — именно так и вышло в первый раз.

**2. Войти в веб-версию** в обычном браузере: `web.budgetbakers.com`, тем же аккаунтом.
Открыть раздел операций и дождаться, пока список нарисуется, — реплика докачивается в это же
время. Внизу видно, сколько документов приехало; ждать, пока число перестанет расти.

**3. Снять базу.** Открыть DevTools (F12), вкладку Console, вставить содержимое
[dump_pouch.js](tools/dump_pouch.js) и выполнить. Скрипт сам найдёт базу
(её имя содержит идентификатор пользователя и у каждого своё), напечатает состав документов
по типам и скачает файл `wallet-pouch` с расширением json в «Загрузки». Размер — около 14 МБ
на 14 тысяч документов.

Скрипт только читает. Ничего в базе Wallet он не меняет и никуда не отправляет.

**4. Положить файл в рабочую папку** — `tasks/wallet-import/artifacts/`, имя оставить
как есть. Папка в `.gitignore`: личные данные в репозиторий не едут.

**5. Разобрать.** Из корня репозитория:

```
python tasks/wallet-import/tools/wallet_export.py   # операции, категории и счета в CSV
python tasks/wallet-import/tools/wallet_probe.py    # описание модели данных в текстовый отчёт
```

`wallet_export.py` печатает сводку: сколько операций, как они разошлись по видам, все ли
переводы парные, сколько записей осталось без имени категории, за какой период данные.
Эту сводку стоит прочитать целиком — она же и есть проверка, что разбор не сломался.

**6. Сверить с независимым источником.** Пока в рабочей папке лежит список операций,
снятый с экрана телефона, сверка запускается так:

```
python tasks/wallet-import/tools/wallet_verify.py
```

Скрипт подбирает часовой пояс, при котором даты выгрузки сходятся с датами на экране,
и показывает расхождения по дням. Расхождение в последних днях означает, что веб-версия
отстала от телефона, — тогда шаг 1 повторяется. Подробнее о том, что именно доказывает
эта сверка, — в [wallet-data.md](wallet-data.md).

## Тупики: что пробовали до этого

Записано, чтобы следующая сессия не прошла тот же круг заново.

- **Экспорт в файл из самого Wallet** — только в платной подписке.
- **`adb backup`** — приложение запрещает резервное копирование, архив приходит пустым
  (47 байт заголовка).
- **Файл базы с телефона** — лежит в приватной папке приложения, без прав root не читается.
  Через `adb` достаётся только кэш карт, данных операций там нет.
- **Снятие списка с экрана телефона** через `uiautomator dump` со свайпами — сработало, но даёт
  куда меньше: ни категорий, ни валюты, ни второй стороны перевода, ни года у старых дат.
  Один месяц снимался несколько минут. Этот путь остаётся на случай, если веб-версия
  однажды перестанет держать базу локально; снятый им сентябрь пригодился как независимый
  источник для сверки.

## Если скрипт консоли не находит базу

- Раздел операций должен быть открыт: до первого захода в него реплика не создаётся.
- Проверить имена локальных баз: `(await indexedDB.databases()).map(d => d.name)`. Нужная
  начинается с `_pouch_user_bb-`.
- Приватное окно не подходит: там IndexedDB своя и пустая.
