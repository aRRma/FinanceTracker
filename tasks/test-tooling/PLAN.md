# План: виды тестов и инструменты

Основание — [SUMMARY.md](SUMMARY.md). Отметки о готовности ставятся только здесь, в [README.md](README.md) — этап целиком.

Общее для всех этапов: новая проверка ломается нарочно в момент написания и падает с внятным сообщением; в конце этапа — полный `dotnet test` и сверка числа тестов с прошлым прогоном.

## 1. Пробелы домена, найденные Stryker

- [ ] `Account.ChangeOpenedOn`: новая дата открытия ровно в день самой ранней операции принимается — граница `>` против `>=`.
- [ ] `Dates.EnsureInRange`: дата ровно на нижней границе принимается, на день раньше — нет.
- [ ] `Money`: `<` и `>` на равных суммах ложны, `!=` различает суммы и валюты.
- [ ] `CategoryRules.ReceiverFor`: защищённая подкатегория отвергается самим `ReceiverFor`, а не только `Category.Delete`.
- [ ] `CategoryRules.EnsureCanMove`: не группа и подкатегория из чужой группы — `ArgumentException`.
- [ ] Текст ошибки: категория в переводе против пропущенной категории (`Transaction`), перенос в группу дохода против расхода (`CategoryRules`). Сверять с ресурсом, а не литералом.

Готово, когда повторный Stryker по домену не показывает этих выживших.

## 2. Сверка с простой моделью на случайных данных

Главный вид тестов, которого нет. Генератор заводит сотни операций через `TransactionFixture`:
- счета разных валют, скрытые и заблокированные;
- переводы, возвраты в универсальных группах;
- даты на границах месяцев.

Наивный подсчёт в памяти отвечает на те же вопросы, что запросы.

- [ ] Пробный тест с CsCheck: подключение, время, вывод зерна на сбое. Новая зависимость — с согласия пользователя; помехи — пробовать FsCheck.
- [ ] Баланс счёта: начальный остаток плюс доходы минус расходы, переводы по сторонам.
- [ ] Лента: страницы от курсора складываются в полный список без потерь и повторов; итог дня равен сумме строк дня по правилам итога дня.
- [ ] Отчёт: группы сходятся с подкатегориями, переводы не входят, возврат вычитается из своей группы, набор счетов отчёта соблюдён.
- [ ] Чистые функции:
  - сумма в копейки и обратно;
  - набор суммы через `AmountExpression`;
  - месяц отчёта строкой и обратно;
  - порядок ключей UUIDv7.
- [ ] Число итераций подобрано так, чтобы полный `dotnet test` оставался в секундах; приём описан в навыке `tests`.

## 3. Stryker как инструмент проекта

- [ ] Stryker в манифест локальных инструментов .NET и файл настроек с обоими тестовыми проектами. Строки `DomainFaults` и `ThrowIfNull` исключены из мутаций, чтобы выжившие были только по делу.
- [ ] Первый прогон по `Finance.Application`: замер времени и оценки, разбор выживших тем же порядком, что в этапе 1.
- [ ] Команда и чтение отчёта — в навык `tests`. Запуск — перед релизом и после крупной правки правил; не на каждую правку и не в CI: прогон идёт минуты.

## 4. Повторяемые сценарии на эмуляторе

- [ ] Помощник `tools/ui.cs` читает цепочку команд из файла.
- [ ] Пять–семь сценариев: счёт, операция, правка, удаление, нарушенное правило, отчёт, ПИН-код. Каждый заканчивается проверкой журнала падений — падение молчит.
- [ ] Прогон на чистом эмуляторе отладочной сборкой и релизным APK перед тегом: отсечение кода ломает отражение только в релизе. Сначала проверить, хватает ли на чистом эмуляторе места под релизную установку.
- [ ] Порядок прогона — в навык `emulator`.
