# Задачи

Долгая работа, у которой есть своё состояние, живёт здесь — папкой на задачу. Внутри всё,
что к ней относится: описание и саммари, этапы со статусом, скрипты в `tools/` и данные
в `artifacts/`. Искать по трём местам сразу больше не нужно.

| Задача | О чём | Состояние |
|---|---|---|
| [schema/](schema/README.md) | Работы по схеме базы: что правим сейчас, что после переноса истории, что ждёт требования | Разобрано; сделана только пакетная вставка при переносе |

Закрытые: перенос истории из Wallet (30 сентября 2026) — итог в [ADR-0014](../docs/adr/0014-wallet-import-one-shot-through-domain-path.md).

## Что где лежит внутри задачи

- `README.md` — точка входа: зачем задача, что сделано, этапы, открытые вопросы. С него начинает новая сессия
- остальные `*.md` — подробности, на которые README ссылается
- `tools/` — скрипты задачи. Инструменты всего проекта остаются в [../tools/](../tools/)
- `artifacts/` — данные и то, что из них собрано. **В репозиторий не попадает**: папка с таким именем отсечена в `.gitignore`

## Чем это отличается от остальных документов

- [../docs/](../docs/) — то, что описывает само приложение: требования, решения, архитектура,
  сценарии, макеты. Живёт, пока живёт приложение
- [../PLAN.md](../PLAN.md) — этапы проекта целиком. У задачи там короткий блок со ссылкой сюда
- `tasks/` — работа, у которой есть начало и конец. Закончится — итог записывается в решение
  (ADR) или в PLAN.md, а папка задачи уходит в архив вне репозитория: в её материалах
  бывают личные данные

Статус задачи держится в одном месте — в её `README.md`. В `PLAN.md` он не дублируется:
два списка галочек разъезжаются на первой же правке.
