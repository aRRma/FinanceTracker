# План: отчёты о сбоях

Основание — [SUMMARY.md](SUMMARY.md). Отметки о готовности ставятся только здесь, в [README.md](README.md) — этап целиком.

Общее для всех этапов: новая проверка ломается нарочно в момент написания и падает с внятным сообщением;
в конце этапа — полный `dotnet test` со сверкой числа тестов, `dotnet build Finance.slnx`; правка, видная
в интерфейсе, — проверка в эмуляторе (чистый `pixel_7_clean`).

## 1. Отчёты о сбоях в прикладном слое

`Finance.Application/Infrastructure/Diagnostics`.

- [ ] Отчёт о сбое: вид, время UTC через `IClock`, версия приложения и сборки, Android, модель, тип исключения и стек с вложенными, след. Сведения об устройстве — параметром из `Finance.App`, не через MAUI.
- [ ] **Текст исключения — только у типов из короткого белого списка** (свои исключения приложения, `SqliteException`); у остальных — тип и стек без текста: `FormatException` несёт введённое значение, `ArgumentOutOfRangeException` — «Actual value was …». Вложенные — по тому же правилу. Тест: исключение с суммой в тексте даёт отчёт без суммы.
- [ ] Файл: синхронная запись с дозаписью, текущий до 256 КБ и один предыдущий; чтение отчётов от новых к старым; очистка. Запись и ротация — под одной блокировкой на процесс: сбой потока и отчёт `Guarded` могут прийти одновременно. Тест: параллельные записи на границе ротации не теряют и не перемешивают отчёты.
- [ ] Сбой самой записи не бросается наружу (фильтр у `catch` — без голого `catch (Exception)`); почему синхронно — комментарий.
- [ ] `DomainException` не пишется; `DatabaseMigrationException` — с вложенным.
- [ ] Регистрация в `AddFinance` с путём к папке параметром, как у базы.
- [ ] Тесты: формат, ротация на границе размера, порядок чтения, очистка, доменное правило не пишется, повреждённый хвост файла (оборванная запись) не мешает чтению остальных.

## 2. Перехват сбоев в приложении

- [ ] `MainApplication`: `AndroidEnvironment.UnhandledExceptionRaiser`, `AppDomain.CurrentDomain.UnhandledException`, `TaskScheduler.UnobservedTaskException` (предупреждение) — подключение до `CreateMauiApp`.
- [ ] Свой `Java.Lang.Thread.DefaultUncaughtExceptionHandler`: пишет стек и отдаёт прежнему обработчику (`XamarinUncaughtExceptionHandler`).
- [ ] Один сбой — один отчёт: на главном потоке срабатывают до трёх обработчиков подряд; пишет первый, остальные видят признак и молчат. Тест на признак.
- [ ] `Guarded.ReportAsync` и сбой перечитывания экрана пишут отчёт; журнал Android под тегом `Finance` остаётся — его читает `tools/ui.cs -- crash`.
- [ ] `DevicePinStore.ReadAsync` — отчёт-предупреждение.
- [ ] Проверка в эмуляторе каждого способа из таблицы SUMMARY.md; релизная сборка — отсечение кода не должно выбросить обработчики.

## 3. След действий

- [ ] Кольцо на 30 событий в прикладном слое; принимает только типизированные события (маршрут, файл и метод, член `Invariant`, событие жизненного цикла), без свободной строки.
- [ ] Маршрут без параметров; тест — параметры с ключом и видом отрезаются.
- [ ] `Shell.Navigated` в `AppShell`; `[CallerMemberName]` и `[CallerFilePath]` у `Guarded.Run` и `Guarded.Execute`; уход в фон, возврат, смена темы, `OnTrimMemory` в `MainActivity`; член `Invariant` из `FormViewModel` и `Guarded`.
- [ ] `setProcessStateSummary` при каждом переходе и действии: экран и последнее действие в пределе, найденном на этапе 0, с обрезкой.
- [ ] Тесты: порядок, вытеснение старых, обрезка summary по байтам UTF-8, а не по символам.

## 4. Причины прошлых завершений

- [ ] Интерфейс истории завершений в прикладном слое, реализация на `ActivityManager` в `Platforms/Android`.
- [ ] При старте — записи новее метки из `Preferences`; метка двигается после записи отчёта. Обычные завершения (`EXIT_SELF` с кодом 0, `USER_REQUESTED`, `USER_STOPPED`, `PACKAGE_UPDATED`) пропускаются; `EXIT_SELF` с другим кодом — сбой .NET вне главного потока, он даёт отчёт, если обработчик не успел.
- [ ] `REASON_CRASH` и `EXIT_SELF` с кодом не 0, о которых уже есть отчёт обработчика, второй раз не пишутся — сверка по времени и pid; тест.
- [ ] Зависание: из текстовой трассы (около 56 КБ) — только стек потока `main`, до 16 КБ, внутри отчёта. Отдельных файлов трасс нет: ни зависания, ни нативного падения целиком не хранятся. Зависание, после которого поток ожил, система не записывает — не ловится, это в «Чего это не даст».
- [ ] Нативное падение: свой читатель protobuf по полям `tombstone.proto` — сигнал, сообщение о прерывании, стек упавшего потока с именами функций; памяти, регистров и карт не хранить. В коде — «нативная трасса» (`NativeTrace`), не `Tombstone`: надгробие в словаре занято обменом.
- [ ] Тесты: выбор записей по метке, пропуск обычных завершений, разбор трассы на образце. Образцы сняты на этапе 0 и лежат в папке `artifacts` задачи; нативный весит 280 КБ и несёт список открытых файлов и куски памяти — в тесты идёт не он, а образец, урезанный до нужных полей своим кодом записи protobuf.
- [ ] Проверка в эмуляторе: `kill -SEGV`, `am crash`, зависание с закрытием. Убийство в фоне эмулятор не воспроизводит: `am kill` записывается как `USER_REQUESTED`.

## Отложено и отклонено

- **Облачный сервис сбоев (Sentry) — отложен** до обмена с сервером: нужна сеть, отчёт уходит третьей стороне.
- **Аудит изменений данных — отложен:** появится с журналом изменений обмена.
- ~~Сообщение «приложение закрылось с ошибкой» при следующем запуске~~ — пользователь выбрал тихий вариант: отчёты ждут в «О программе».
- ~~Имя со словом «журнал»~~ — словарь уже запрещает «журнал» как другое имя ленты счёта, а «журналом изменений» назван обмен.
- ~~Текст любого исключения в отчёте~~ — в текстах бывают введённые значения; пишется только у белого списка типов.
- ~~Сбор действий пользователя в облако~~ — пользователь один, данные о финансовом поведении в чужое облако не уходят.
- ~~Постоянный замер скорости~~ — задержек нет; при появлении — разовый замер профилировщиком.
- ~~След действий на диске на каждое событие~~ — лишняя запись во флеш; след уходит в файл при сбое, экран — в summary.
- ~~Трасса нативного падения целиком~~ — в ней бывают куски памяти с данными пользователя.
- ~~Чтение журнала Android (`logcat`) самим приложением~~ — приложение перехватывает свои сбои само, чужие строки не нужны.
