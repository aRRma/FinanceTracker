# MVP — одно устройство без сети; сервер, когда появится, не исполняет доменную логику

Границы MVP: один пользователь, одно устройство, к сети приложение не обращается. Обмен между устройствами отложен целиком — сервер, протокол, очередь отправки, слияние правок (SYN-*). Отчёт о расходах и доходах по группам за месяц, наоборот, входит в MVP (FR-RPT-*). Когда обмен появится, сервер будет только хранилищем строк: без доменных проверок, без внешних ключей, без расчётов (SYN-18, SYN-20, SYN-21); проект `Finance.Contracts` не ссылается на `Finance.Domain`, чтобы сервер не получил доменную логику транзитивно.

**Обмен в MVP** отвергнут: половина спецификации и самая дорогая в отладке часть — слияние правок с двух устройств — ради второго телефона, которого у пользователя пока нет. **MVP без отчёта** отвергнут: без ответа на вопрос «куда ушли деньги» учёт операций не окупает усилий на ввод, и проект не доживёт до следующего этапа. **Проверки на сервере** отвергнуты: источник правды — локальная база, инварианты проверяются при вводе, а сервер, повторяющий их, разошёлся бы с клиентом при первом же изменении правил. **Общая сборка контрактов и домена** отвергнута по той же причине.

Цена — единственная копия данных живёт на устройстве. Копию вне него даёт выгрузка в файл (ADR-0015), сделанная после MVP, но сохранять её — забота пользователя.
