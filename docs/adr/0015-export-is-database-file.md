# Выгрузка — файл базы SQLite; восстановление мигрирует файл до записи

Выгрузка — сам файл базы, снятый `VACUUM INTO` (слайс `Features/Export`, экран «Данные» [D-10]). Файл сохраняется на выбор двумя путями: в папку на самом телефоне через системное окно выбора места (`ACTION_CREATE_DOCUMENT`, `DeviceFileSaver` в `Platforms/Android`) или через системное «Поделиться» — Google Диск, Telegram, почта. Восстановление принимает файл во временную папку, проверяет его, доводит до текущей схемы теми же миграциями, что и базу при обновлении, и только готовый переносит в рабочую базу встроенным копированием SQLite (`SqliteConnection.BackupDatabase`), после чего приложение перезапускается.

**Переезжает всё как есть:** идентификаторы, метки, мягко удалённые строки — надгробия нужны будущему обмену (ADR-0003), — настройки и версия стартового набора. Набор поэтому повторно не применяется: его версия приезжает вместе с ним.

**Порядок проверок.** Целостность (`PRAGMA integrity_check`) — затем история миграций: в ней обязана быть наша первая миграция, иначе это чужая база SQLite, и не должно быть незнакомых приложению — EF сам базу из будущей версии не отвергает, он накатывает известные миграции и молча пропускает лишние строки истории. Затем миграция временного файла. Отказ на любом шаге — ожидаемый исход с причиной для пользователя, а не сбой; временный файл удаляется, рабочая база не тронута (NFR-27).

**Миграция — до записи, а не после.** Мигрируй выгрузку уже на месте рабочей базы, неудача оставила бы приложение без данных: откат вернул бы ту же выгрузку, а текущие данные уже стёрты.

**Копирование SQLite, а не подмена файла.** `BackupDatabase` пишет в рабочую базу одной транзакцией прямо на ходу: при сбое база остаётся прежней, и не нужны ни закрытие пула соединений, ни удаление журнала рядом с базой, ни отложенная подмена при следующем запуске. В базу в режиме WAL копирование принимает только файл с тем же размером страницы — расхождение даёт ошибку, а не порчу данных.

**Перезапуск, а не перечитывание.** Карточки и формы при появлении не перечитываются, стеки вкладок живут свои, пояс и тема запомнены при запуске. Открытая в другой вкладке карточка сохранила бы правку в объект, которого в восстановленной базе нет. `Application.Quit()` перезапуском не является: на Android процесс и синглтоны контейнера живут дальше, — поэтому запуск новой задачей и завершение процесса.

**Замена, а не слияние, — и предупреждение с отсчётом.** Восстановление стирает текущие данные целиком. Если в базе есть счета или операции, перед заменой показывается красное предупреждение — сколько счетов и операций будет удалено, — и его кнопка оживает только через пять секунд — так устроены необратимые действия в настройках телефонов. Пустая база (свежая установка) заменяется без вопроса: терять нечего. Дополнено 5 октября 2026: в счёт идут ещё свои категории и места — база, где завели только их, заменялась молча; свою категорию от стартовой отличает версия ключа (UUIDv7 против UUIDv5). Предупреждение — на месте строк экрана, а не системным диалогом: в диалоге кнопку не погасить.

**Отвергнуто пока: «дополнить данными из файла».** Слияние по ключам с правилами будущего обмена (побеждает более свежая правка, удаление сильнее изменения) — по сути половина обмена, который отложен. Нерешённое: одинаковые имена с разными ключами (две «Карты») нарушают уникальность имён, а операции, введённые вручную на обоих телефонах, задвоятся неразличимо. Возвращаться — отдельной задачей вместе с правилами слияния для обмена.

**Цена.** Шифрования нет: в файле вся история, и лежит он там, куда его отдал пользователь. Пароль — отдельное решение, только по просьбе. Восстановление не отменяется: копии текущей базы для отмены нет.

**Будущий обмен.** Восстановив одну выгрузку на двух телефонах, получим два устройства с одним состоянием. Сейчас ни идентификатора устройства, ни очереди отправки нет. С появлением обмена состояние, привязанное к устройству, при восстановлении сбрасывается.

**Отвергнуто: JSON с сущностями.** Читается человеком, но это второе описание схемы: правится при каждой миграции, а забытое поле теряется молча.

**Отвергнуто: автокопирование Android (`allowBackup`).** Сроки и состав решает Google, файл базы может уйти без журнала — нерабочим, а финансы попадают в облако без явного согласия. Остаётся выключенным (NFR-08).

**Отвергнуто: метка `PRAGMA application_id`.** Свою базу отличает история миграций; метку пришлось бы ставить отдельной правкой, а в установленных базах её нет.
