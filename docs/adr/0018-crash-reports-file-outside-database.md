# Отчёты о сбоях: файл на телефоне, вне базы, без личных данных

Сбой на телефоне не оставлял читаемого следа: журнал Android с телефона не достать, а необработанные исключения .NET, падения внутри Java, нативные падения и зависания не ловило ничто (FR-SET-09). Отчёт о сбое пишется на самом телефоне, а наружу уходит только руками — «Поделиться».

**Файл вне базы, а не таблица.** Отчёт должен записаться и о сбое самой базы — сорванной миграции, испорченном файле, — и читаться, когда база не поднялась. Таблица уехала бы с выгрузкой (ADR-0015), а отчёты о чужом телефоне на новом не нужны. Поэтому отчёты создаются раньше контейнера служб и берут время у `TimeProvider`, а не у часов приложения.

**Без личных данных.** Файл отправляют через мессенджер, и он обязан быть безопасен целиком: ни сумм, ни имён, ни заметок, ни текста нарушенных правил. Текст исключения пишется только у короткого белого списка типов, стек Java — без сообщений; от нарушенного правила остаётся имя члена `Invariant`. След действий держит только имена из кода.

**Причины прошлых завершений — у системы.** Нативное падение и зависание обработчик .NET не видит: процесс умирает раньше. При следующем запуске приложение забирает у Android записи о прошлых завершениях и пишет отчёт сам; экран и последнее действие перед сбоем доходят до этой записи сводкой процесса.

**Отвергнуто: облачный сервис сбоев (Sentry).** Нужна сеть, которой у приложения нет (SYS-04), и отчёт уходит третьей стороне. Отложено до обмена с сервером.

**Отвергнуто: только системный журнал.** С телефона его не достать без кабеля и режима разработчика.

**Цена.** Отчёт не приходит сам: пока пользователь не нажал «Поделиться», о сбое никто не знает. Файл ограничен по размеру, и старые отчёты вытесняются новыми.
