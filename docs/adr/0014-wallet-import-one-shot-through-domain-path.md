# Перенос из Wallet — разовый и через доменный путь

История из Wallet переносится один раз, в пустую базу; код переноса — отдельная сборка `Finance.Import` (раздел ниже). Файл переноса готовится вне приложения, категории Wallet в нём уже сопоставлены с ключами стартового набора. Функцией импорта для пользователя это не считается: импорт вне MVP, поле `external_id` перенос не заполняет.

**Итог.** Перенос выполнен 30 сентября 2026 релизом 1.0.8 — тогда ещё строкой на экране «О программе», — сверка балансов и сумм по месяцам с Wallet сошлась. Материалы задачи — разбор данных, сопоставление категорий, скрипты — вынесены из репозитория в архив рядом с ним: в них личные данные.

**Запись идёт тем же пишущим путём, что и формы.** Счёт, место и операция создаются доменными фабриками, операция проходит `TransactionRules`, всё — одной транзакцией. Запись в обход правил оставила бы в базе строки, которые форма потом не смогла бы сохранить при правке.

**Только в пустую базу.** Пустота проверяется внутри транзакции и с учётом удалённых записей: второй перенос поверх первого удвоил бы балансы, а повтор имени удалённого счёта был бы неотличим от ошибки сопоставления. Стартовый набор пишется один раз за жизнь установки (ADR-0006), поэтому база для переноса — свежая. Версию набора обработчик не проверяет: на базе со старым набором перенос остановится на первой неизвестной категории и откатится целиком.

~~**Слайс остаётся в приложении до проверки восстановления из выгрузки на телефоне** (ADR-0015), затем удаляется.~~ Пересмотрено 4 октября 2026, после проверки восстановления: перенос может понадобиться будущим клиентам, а с ним и переносы из других приложений.

**Перенос — отдельная сборка `Finance.Import`, на которую приложение не ссылается** (сверяет `ProjectReferenceTests`). Телефону код переноса не нужен: восстановление из выгрузки (ADR-0015) уже принимает любой файл нашей базы, проверяет и мигрирует его. Перенос запускают на рабочей машине: свежая база со стартовым набором, запись этим обработчиком, файл базы — клиенту, а он открывает его через «Данные → Восстановить из файла». Инструмента запуска пока нет — он пишется вместе с первым таким переносом; что такая база проходит восстановление и приезжает целиком, сверяет тест `База_с_переносом_принимается_восстановлением`. Тесты переноса идут обычным `dotnet test`, поэтому код не гниёт. Доступ к строкам таблиц перенос получает через `InternalsVisibleTo`: обе сборки собираются из одного коммита, а открытый интерфейс записи ради одного переноса попал бы в каждый пакет приложения. Цена — переносу технически открыта запись мимо домена; удерживают от неё правило выше и тесты отказов по правилам.

**Отвергнуто: спрятать строку и оставить код в приложении** — мёртвый код ехал бы в каждом пакете, а файл для него всё равно готовится на рабочей машине. **Отвергнуто: перенос внутри приложения для клиента без нас** — данные Wallet снимаются через инструменты разработчика веб-версии, на телефоне клиенту этого не сделать.

**Операция чужого вида при подготовке файла не ложится в чужую группу.** Доход из расходной категории Wallet ушёл в «Доход → Возвраты и вычеты», расход из доходной — в «Финансы → Прочее», с заметкой об источнике: разбирать возвраты всей истории поштучно дольше, чем стоит точность. Поэтому возвраты прошлых лет не вычитаются из расхода своей категории, а итог дня в ленте считается по нашему правилу переводов — оба расхождения с Wallet сознательные.

**Цена.** Нарушенное правило называет себя своим текстом, но без номера записи; номер есть только у ссылки мимо файла.

**Отвергнуто: прямая вставка строк в базу.** Быстрее и не требует доменных фабрик, но обходит инварианты — ровно то, от чего защищает домен.

**Отвергнуто: общая функция импорта.** Требует формата, сопоставления категорий и пакетной отправки при будущем обмене; для одной выгрузки одного человека это работа впустую.
