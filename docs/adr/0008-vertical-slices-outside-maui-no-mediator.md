# Прикладной слой — срезы по функциям в библиотеке вне MAUI, без посредника и репозиториев

Решение из четырёх проектов: `Finance.Domain`, `Finance.Application`, `Finance.App`, `Finance.Domain.Tests`. Код прикладного слоя режется по функциям, а не по техническим слоям: папка `Features/Transactions/Add` содержит команду, обработчик, запросы и модель представления; срезы не ссылаются друг на друга, общий запрос переезжает в инфраструктуру — папку внутри `Application`. В проекте MAUI остаются только страницы, навигация и ресурсы темы. Модели представления вызывают обработчики напрямую через интерфейсы. Доменные типы создаются фабричным методом с полной проверкой, а восстанавливаются из хранилища публичным путём без проверок, с комментарием об этом.

**Слои отдельными проектами** отвергнуты: у инфраструктуры один потребитель, и шов, за которым ничего не меняется, только добавляет ходов; вынести её позже не ломает написанного. **Всё внутри MAUI** отвергнуто: проект MAUI не тестируется обычным xUnit и долго собирается, а обработчики и модели представления — ровно то, что нужно тестировать без эмулятора. **Посредник** отвергнут: `Send(object)` не даёт вызывающему ничего, чего не даёт прямой вызов, и прячет только диспетчеризацию. **Репозиторий на сущность** отвергнут: хранилище одно, адаптер один, второго не предвидится — простые запросы идут без обёрток, составные прячутся за именованными методами. **`internal` с `InternalsVisibleTo`** для пути восстановления отвергнут как усложнение ради видимости; вместо этого метод публичный, а его комментарий обязан предупреждать, что проверок нет.
