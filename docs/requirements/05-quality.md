# Нефункциональные требования

Производительность, надёжность данных, корректность времени, безопасность, оформление. Идентификаторы: `NFR-*`.

## Производительность

| NFR-01 | Открытие главного экрана и загрузка страницы ленты — не более 300 мс при 50 000 операций |
|---|---|
| NFR-02 | Расчёт балансов выполняется запросом к базе, без загрузки операций в память |
| NFR-03 | Выборка операций по счёту использует объединение двух индексированных запросов. Условие с дизъюнкцией по двум колонкам счёта не допускается |
| NFR-04 | Обязательные индексы: составной по счёту, дате операции, `created_at_utc` и ключу — состав и порядок колонок повторяют сортировку из FR-LED-02; отдельный по счёту назначения |
| NFR-05 | Любая операция длительностью более 50 мс выполняется вне потока интерфейса |

## Надёжность данных

| NFR-06 | Перед применением миграции схемы создаётся целостный снимок базы средствами СУБД. При неуспешной миграции выполняется восстановление |
|---|---|
| NFR-07 | Хранится одна последняя резервная копия |
| NFR-26 | Неудачная миграция: снимок восстанавливается, приложение сообщает об ошибке и не запускается — работать со старой схемой новый код не может. Пользователь возвращает предыдущую версию приложения, данные при этом целы |
| NFR-08 | Автоматическое резервное копирование данных приложения средствами операционной системы отключается либо восстановление строится через синхронизацию |
| NFR-09 | Денежные значения хранятся и обрабатываются типом с фиксированной точностью. Использование чисел с плавающей точкой не допускается |
| NFR-10 | Сложение денежных сумм в различных валютах приводит к ошибке на уровне типа (ADR-0004) |

## Корректность времени

| NFR-11 | Моменты времени хранятся в UTC и переводятся в локальную зону только при отображении (ADR-0009) |
|---|---|
| NFR-12 | Календарные даты хранятся без времени и часового пояса и не подвергаются преобразованиям (ADR-0009) |
| NFR-13 | Текущая дата вычисляется как локальная дата пользователя, а не как дата в UTC |
| NFR-14 | Часовой пояс хранится идентификатором зоны, а не числовым смещением (ADR-0009) |

|---|---|
| NFR-16 | Секреты не включаются в состав установочного пакета |

## Сопровождение

| NFR-18 | Доменный слой не зависит от инфраструктуры: ни от средств доступа к данным, ни от пользовательского интерфейса, ни от формата передачи |
|---|---|
| NFR-19 | Инварианты реализованы в доменных типах, а не в обработчиках команд |
| NFR-20 | Проставление меток изменения выполняется в единой точке сохранения, а не в каждом обработчике. Наполнение очереди отправки встраивается туда же, когда появится обмен |
| NFR-21 | Набор значков поставляется в составе приложения. Загрузка из сети не выполняется |
| NFR-22 | Неизвестный ключ значка отображается запасным значком и не приводит к ошибке |
| NFR-23 | Обе темы оформления полноценны: все экраны, включая диалоги и клавиатуру, следуют выбранной теме без остаточных светлых или тёмных участков |
| NFR-24 | Цвета задаются только именованными токенами темы. Прямые значения цвета в разметке экранов запрещены |
| NFR-25 | Смысловые цвета — доход, отрицательный баланс, необратимые действия — различимы в обеих темах; контраст текста не ниже WCAG AA, зоны касания не меньше 48×48 dp |
