# Нефункциональные требования

Производительность, надёжность данных, корректность времени, безопасность, сопровождение и оформление. Идентификаторы: `NFR-*`.

## Производительность

| NFR-01 | Открытие главного экрана и загрузка страницы ленты — не более 300 мс при расчётном объёме данных (SYS-06). Замером на устройстве не проверялось: время держат планы запросов (NFR-03, NFR-04), которые сверяют тесты |
|---|---|
| NFR-02 | Расчёт балансов выполняется запросом к базе, без загрузки операций в память |
| NFR-03 | Выборка операций по счёту использует объединение двух индексированных запросов. Условие с дизъюнкцией по двум колонкам счёта не допускается |
| NFR-04 | Индексы операций — только по неудалённым строкам: составной по счёту списания, дате операции, `created_at_utc` и ключу — порядок колонок повторяет сортировку из FR-LED-02; такой же по счёту зачисления; такой же без счёта — для общей ленты. Прочие — под отчёт и счётчики мест (`TransactionConfiguration`) |
| NFR-05 | Чтение и запись базы и файлов идут вне потока интерфейса: ввод-вывод асинхронный на всём пути |

## Надёжность данных

| NFR-06 | Перед применением миграции схемы создаётся целостная резервная копия базы средствами СУБД. Копия одна: прежняя заменяется только готовой новой |
|---|---|
| ~~NFR-07~~ | Объединено с NFR-06: хранится одна последняя резервная копия |
| NFR-26 | Неудачная миграция: резервная копия восстанавливается, приложение сообщает об ошибке и не запускается — работать со старой схемой новый код не может. Пользователь возвращает предыдущую версию приложения, данные при этом целы. Не удалась сама копия — миграция не начинается, и об этом тоже сообщается. При первом создании базы копии нет: сбой показывается сообщением без восстановления |
| NFR-08 | Автоматическое резервное копирование данных приложения средствами операционной системы отключено |
| NFR-27 | Восстановление из выгрузки не меняет рабочую базу, пока присланный файл не прошёл проверку целостности и истории миграций и не доведён до текущей схемы. Запись в рабочую базу — одной транзакцией средствами СУБД: при сбое база остаётся прежней |
| NFR-09 | Денежные значения хранятся и обрабатываются типом с фиксированной точностью. Использование чисел с плавающей точкой не допускается (INV-32) |
| NFR-10 | Сложение денежных сумм в различных валютах приводит к ошибке на уровне типа (ADR-0004, INV-33) |

## Корректность времени

| NFR-11 | Моменты времени хранятся в UTC и переводятся в локальную зону только при отображении (ADR-0009) |
|---|---|
| NFR-12 | Календарные даты хранятся без времени и часового пояса и не подвергаются преобразованиям (ADR-0009) |
| NFR-13 | Текущая дата вычисляется как локальная дата пользователя, а не как дата в UTC |
| NFR-14 | Часовой пояс хранится идентификатором зоны, а не числовым смещением (ADR-0009) |

## Безопасность

| ~~NFR-15~~ | Отложено вместе с обменом: обмен с сервером в эксплуатации только по TLS. Раньше дублировалось как SYS-05 |
|---|---|
| NFR-16 | Секретов в установочном пакете нет. Ключ подписи и пароль к нему — только в секретах репозитория |
| NFR-28 | ПИН-код не хранится ни открыто, ни в базе: хранится только след медленной функции со своей солью в хранилище, зашифрованном ключом Android; сравнение следов — за постоянное время (ADR-0017) |
| NFR-29 | Длительность фона для защиты входа считается по часам, идущим во время сна телефона и не зависящим от перевода времени (ADR-0017) |
| ~~NFR-17~~ | Отложено вместе с обменом: отсутствие учётных данных не препятствует локальной работе |

## Сопровождение

| NFR-18 | Доменный слой не зависит от инфраструктуры: ни от средств доступа к данным, ни от пользовательского интерфейса, ни от формата передачи |
|---|---|
| NFR-19 | Инварианты реализованы в доменных типах, а не в обработчиках команд |
| NFR-20 | Проставление меток изменения выполняется в единой точке сохранения, а не в каждом обработчике. Наполнение очереди отправки встраивается туда же, когда появится обмен |

## Оформление

| NFR-21 | Набор значков поставляется в составе приложения |
|---|---|
| NFR-22 | Неизвестный ключ значка отображается запасным значком и не приводит к ошибке |
| NFR-23 | Обе темы оформления полноценны: все экраны, включая диалоги, клавиатуру суммы и клавиатуру ПИН-кода, следуют выбранной теме без остаточных светлых или тёмных участков |
| NFR-24 | Цвета задаются только именованными токенами темы, прямые значения цвета в разметке запрещены. В макетах это сверяет `PaletteTests`, в разметке приложения — дисциплина |
| NFR-25 | Смысловые цвета — доход, отрицательный баланс, необратимые действия — различимы в обеих темах. Контраст текста не ниже WCAG AA (4,5), значка на заливке знака счёта и вида сбоя — не ниже 3; сверяет `ContrastTests` по таблице пар, часть пар — в одной теме. Зоны касания не меньше 48×48 dp — общим стилем |
