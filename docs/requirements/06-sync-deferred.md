# Синхронизация — отложено

**Вне MVP.** В MVP одно устройство одного пользователя, обмен с сервером не реализуется. Раздел сохранён целиком: поля схемы под него заведены сразу, чтобы не переделывать базу. Идентификаторы: `SYN-*`.

Типы колонок на сервере (PostgreSQL), намеченные заранее: ключ — `uuid`, момент — `timestamptz`, дата — `date`, деньги — `numeric(19,2)`, валюта — `char(3)`, признак — `boolean`, перечисление и текст — `text`. Хранение на устройстве — в разделе «Конвенции» [02-domain.md](02-domain.md).

## Модель данных обмена

| SYN-01 | Источник правды — локальная база устройства |
|---|---|
| SYN-02 | Курсор — монотонно возрастающий счётчик изменений на стороне сервера. Использование меток времени в качестве курсора не допускается |
| SYN-03 | Очередь отправки хранит множество ключей изменённых сущностей. Повторные изменения одной сущности схлопываются |
| SYN-04 | Состояние сущности читается в момент отправки, а не в момент постановки в очередь |
| SYN-05 | Удаление передаётся надгробием. Физическое удаление строк в MVP не выполняется — кроме строк настроек: они не сущности и в обмен не идут (SYN-23) |

## Протокол

| SYN-06 | Каждый запрос содержит номер версии протокола |
|---|---|
| SYN-07 | Отправка выполняется пачками ограниченного размера |
| SYN-08 | Пачка применяется на сервере построчно. Ответ содержит список фактически принятых ключей |
| SYN-09 | Очередь отправки очищается только по списку принятых ключей |
| SYN-10 | Применение изменений идёт в порядке: счета, места, группы, подкатегории, операции |
| SYN-11 | Клиент буферизует полученные изменения и упорядочивает их самостоятельно |
| SYN-12 | Повторная отправка не создаёт дублей за счёт вставки с обновлением по ключу |
| SYN-13 | Одно нажатие кнопки выполняет одну итерацию цикла: получение, слияние, отправка, фиксация курсора |

## Разрешение конфликтов

| SYN-14 | Побеждает запись с более поздним `updated_at_utc`, сравнение идёт по строке целиком |
|---|---|
| SYN-15 | Удаление имеет безусловный приоритет над изменением, независимо от меток времени |
| SYN-16 | Метка времени проставляется часами клиента без коррекции |
| SYN-17 | Сервер фиксирует в журнале факт получения метки, существенно опережающей его собственное время |

## Разделение ответственности

| SYN-18 | Слой синхронизации не проверяет доменные инварианты. Полученные строки применяются как есть (ADR-0007) |
|---|---|
| SYN-19 | Доменные инварианты проверяются исключительно при вводе данных пользователем |
| SYN-20 | Внешние ключи на таблицах сервера не создаются. Ссылочную целостность обеспечивает клиент |
| SYN-21 | Сервер не выполняет расчётов, не строит выборок по домену и не хранит производных значений |

## Границы синхронизируемого

| SYN-22 | Синхронизируются свойства доменных сущностей, включая порядок счетов и признак «скрытый» |
|---|---|
| SYN-23 | Не синхронизируются строки настроек — счёт по умолчанию, версия применённого стартового набора, часовой пояс, тема оформления — и защита входа: она хранится вне базы (ADR-0017) |
| SYN-24 | Массовых правок по действию пользователя две: перенос операций при удалении подкатегории и удаление выделенных операций из ленты (FR-LED-08); разовые исключения — миграции `MergeServiceGroups` (с метками изменения), `AcceptsAnyKind` (без меток: признак проставляет каждая установка сама, ADR-0013) и `AddAccountColorAndIcon` (без меток: цвета раздаёт каждая установка сама, ADR-0016). Изменяется каждая затронутая операция — у удалённой своё надгробие, — изменения уходят в очередь обычным порядком |
| SYN-25 | Доменные правила, которые обмен может обойти, и что делать при слиянии. Валюта счёта (INV-11): другое устройство может держать офлайн неотправленную операцию по счёту — учёт удалённых операций сужает окно до операции, которая никогда не доезжала. Удаление счёта (INV-35): операция, записанная офлайн по счёту, удалённому здесь, придёт на удалённый счёт — слияние обязано либо вернуть счёт, либо не принять операцию. Удаление подкатегории (INV-20): операция, записанная офлайн в удалённую подкатегорию, показывается с её названием, а сама подкатегория в выборе не предлагается; перенос в приёмник при получении изменений не переигрывается (SYN-18) |
