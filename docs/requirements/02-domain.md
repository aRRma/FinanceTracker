# Доменная модель и инварианты

Сущности, поля, конвенции именования и правила, которые обязаны соблюдаться всегда. Идентификаторы: `INV-*`.

## Счёт (Account)

| Поле | Тип C# | Описание |
|---|---|---|
| `key` | `Guid` | UUIDv7, генерируется клиентом, первичный ключ |
| `name` | `string` | Наименование |
| `type` | `AccountType` | Наличные или карта. Влияет только на отображение |
| `currency` | `Currency` | RUB, USD или EUR |
| `color` | `AccountColor` | Цвет знака счёта, один из восьми; не обязан быть уникальным (ADR-0016) |
| `icon` | `string?` | Значок, выбранный руками. Пусто — значок по типу и признаку «скрытый» (ADR-0016) |
| `opening_balance` | `Money` | Начальный остаток (ADR-0010). Валюта берётся из `currency` того же счёта, отдельной колонки не имеет |
| `opened_on` | `DateOnly` | Дата, с которой действует начальный остаток |
| `excluded_from_totals` | `bool` | «Скрытый»: счёт не входит ни в подытог доступных к тратам, ни в итоги дня, ни в отчёт по умолчанию — в отчёт его добавляют руками (FR-RPT-12) |
| `is_closed` | `bool` | «Заблокированный»: выведен из употребления, обратимо (FR-ACC-06). Дата блокировки не хранится — ничем не используется |
| `sort_order` | `int` | Порядок в списке счетов |
| `created_at_utc` | `DateTimeOffset` | |
| `updated_at_utc` | `DateTimeOffset` | |
| `deleted_at_utc` | `DateTimeOffset?` | Надгробие мягкого удаления |
| `synced_at_utc` | `DateTimeOffset?` | Подтверждение доставки на сервер. Заведено под обмен и кодом пока не читается; роль рядом с очередью отправки (SYN-03) решается вместе с обменом |
| `external_id` | `string?` | Резерв под будущий импорт |

## Категория (Category)

| Поле | Тип C# | Описание |
|---|---|---|
| `key` | `Guid` | UUIDv7; у категорий стартового набора и строк, заведённых миграциями, — детерминированный UUIDv5 (ADR-0006) |
| `parent_key` | `Guid?` | Заполнен только на втором уровне. Им уровень и задаётся: отдельной колонки уровня нет, два источника одного факта разошлись бы, а путь восстановления их не сверяет |
| `kind` | `CategoryKind?` | Доход или расход. Задаётся только на первом уровне, у подкатегории пусто |
| `accepts_any_kind` | `bool?` | Группа принимает операции обоих видов (ADR-0013). Задаётся только на первом уровне, у подкатегории пусто; после создания не меняется |
| `name` | `string` | |
| `icon` | `string` | Устойчивый ключ значка из набора, зашитого в приложение |
| `role` | `CategoryRole` | Обычная, приёмник группы или служебная. Единственный признак, по которому приёмник и неудаляемые категории отличаются от прочих: имя категории пользователь вправе изменить (FR-CAT-03) |
| `exclude_from_reports` | `bool` | Для служебных категорий. От `role` независим: «не показывать в отчёте» и «не удаляется» — разные вопросы |
| `created_at_utc`, `updated_at_utc`, `deleted_at_utc`, `synced_at_utc`, `external_id` | | Как у счёта |

Приёмник группы — подкатегория с ролью `Other`: в большинстве групп она называется «Прочее», в группах «Без категории» — как сама группа.

Ссылка операции на мягко удалённую подкатегорию допустима. У неудалённых операций в MVP она не возникает: удаление переносит их по INV-20 в той же транзакции. Мягко удалённые операции остаются на удалённой подкатегории, и их не показывает ни один экран. Как такая ссылка появится с обменом — SYN-25.

## Место (Place)

Справочник мест, с которыми происходят операции: магазины, работодатели, банки, клиники. Одна операция ссылается не более чем на одно место.

| Поле | Тип C# | Описание |
|---|---|---|
| `key` | `Guid` | UUIDv7 |
| `name` | `string` | |
| `created_at_utc`, `updated_at_utc`, `deleted_at_utc`, `synced_at_utc`, `external_id` | | Как у счёта |

Ссылка операции на мягко удалённое место допустима. Массовое обнуление ссылок запрещено: история остаётся такой, какой её ввели, а при обмене массовая правка породила бы лишние изменения и конфликты.

## Операция (Transaction)

| Поле | Тип C# | Описание |
|---|---|---|
| `key` | `Guid` | UUIDv7 |
| `kind` | `TransactionKind` | Доход, расход или перевод |
| `source_account_key` | `Guid` | Счёт списания. У расхода и дохода — единственный счёт операции |
| `target_account_key` | `Guid?` | Счёт зачисления, только для перевода |
| `amount` | `Money` | Всегда положительная. Валюта — валюта счёта списания, отдельной колонки не имеет |
| `target_amount` | `Money?` | Сумма зачисления в валюте счёта зачисления. Заполнена у любого перевода: при совпадающих валютах равна `amount` (INV-03, INV-05). В форме при одной валюте не запрашивается |
| `category_key` | `Guid?` | Подкатегория |
| `place_key` | `Guid?` | Место. Необязательно, запрещено для перевода |
| `occurred_on` | `DateOnly` | Календарная дата операции |
| `note` | `string?` | До 1000 знаков |
| `created_at_utc`, `updated_at_utc`, `deleted_at_utc`, `synced_at_utc`, `external_id` | | Как у счёта |

## Настройки

Таблица `settings` — строки «имя — значение»: версия применённого стартового набора, часовой пояс, выбранный руками, тема и счёт по умолчанию, выбранный руками. Строки настроек — не сущности: у них нет меток и надгробий, возврат к системному значению удаляет строку, в обмен они не идут (SYN-23). Защита входа хранится вне базы (ADR-0017).

## Конвенции

- Суффикс `_at_utc` — момент времени, всегда UTC.
- Суффикс `_on` — календарная дата, без времени и часового пояса.
- Все внешние ссылки идут на `key`. Иных идентификаторов у сущностей нет. Внешних ключей в базе нет: ссылки держит приложение (decisions.md).
- Хранение в SQLite: ключ, дата и момент — TEXT в каноническом виде (ADR-0002, ADR-0009), перечисление — TEXT с именем члена, `bool` — INTEGER, деньги — INTEGER целыми копейками (ADR-0011).
- Правила INV-01, INV-13, INV-14, INV-15, INV-19, INV-20, INV-21 и INV-25 домен не проверяет исключением: их держит устройство типов, обработчик или форма. Тест есть у каждого.

## Операции

| INV-01 | Суммы операций всегда положительны. Знак определяется видом операции, а не знаком суммы (ADR-0004). Начальный остаток счёта — не операция и бывает отрицательным: долг по карте · `Invariant.AmountSignComesFromKind` |
|---|---|
| INV-02 | `amount` и заполненная `target_amount` строго больше нуля · `Invariant.AmountIsPositive` |
| INV-03 | `target_account_key` и `target_amount` заполнены тогда и только тогда, когда вид операции — перевод · `Invariant.TargetOnlyInTransfer` |
| INV-04 | В переводе счёт списания и счёт зачисления не совпадают · `Invariant.TransferAccountsDiffer` |
| INV-05 | Если валюты счетов перевода совпадают, `amount` и `target_amount` равны · `Invariant.SameCurrencyTransferAmountsEqual` |
| INV-06 | Категория обязательна для дохода и расхода, запрещена для перевода · `Invariant.CategoryOnlyInIncomeAndExpense` |
| INV-07 | Категория операции всегда второго уровня · `Invariant.CategoryIsSubcategory` |
| INV-29 | Вид категории совпадает с видом операции — либо группа универсальна и принимает оба вида (ADR-0013) · `Invariant.CategoryKindMatchesTransaction` |
| INV-08 | `occurred_on` не раньше `opened_on` обоих задействованных счетов · `Invariant.TransactionNotBeforeAccountOpened` |
| INV-09 | `occurred_on` находится в диапазоне от 2000 года до текущей даты включительно · `Invariant.TransactionDateInRange` |
| INV-10 | Длина заметки без краевых пробелов не превышает 1000 знаков; пустая заметка не хранится · `Invariant.NoteWithinLimit` |
| INV-22 | Место необязательно для дохода и расхода и запрещено для перевода · `Invariant.PlaceNotInTransfer` |
| INV-27 | Заблокированный счёт недопустим в новой операции и при смене счёта в существующей — ни счётом списания, ни счётом зачисления. Исключение — счёт, уже стоящий в этой операции любой стороной. Уже записанные операции заблокированного счёта правятся и удаляются свободно. Проверка межтабличная, как INV-08 · `Invariant.ClosedAccountNotInNewTransaction` |
| INV-19 | Редактирование операции — замена состояния целиком. Изменению подлежат все поля, включая вид операции · `Invariant.EditReplacesWholeState` |
| INV-25 | Смена вида операции на форме немедленно стирает поля, запрещённые новым видом: при переходе в перевод — категорию и место, при переходе из перевода — счёт зачисления и сумму зачисления. Скрытого состояния не сохраняется: возврат прежнего вида требует ввести поля заново. Домен смесь полей отвергает (INV-03, INV-06, INV-22) · `Invariant.KindChangeClearsForbiddenFields` |

## Суммы

| INV-24 | Сумма операции, сумма зачисления и начальный остаток по модулю не превышают 999 999 999 999,99 в валюте своего счёта; баланс и итоги пределом не ограничены · `Invariant.AmountWithinLimit` |
|---|---|
| INV-32 | Сумма записана не больше чем двумя знаками после запятой, и считаются записанные знаки, а не значение: `1.500` отвергается наравне с `1.505` · `Invariant.AmountInWholeKopecks` |
| INV-33 | Суммы в разных валютах не складываются, не вычитаются и не упорядочиваются: общей суммы по валютам не существует (ADR-0004). Равенство сумм разных валют — просто «не равны» · `Invariant.CurrenciesNeverMixed` |

## Счета

| INV-11 | Валюта счёта не может быть изменена после появления первой операции по нему. Мягко удалённые операции учитываются наравне с живыми: достаточно, чтобы операция по счёту существовала когда-либо · `Invariant.CurrencyFixedOnceUsed` |
|---|---|
| INV-12 | `opened_on` сдвигается назад в пределах INV-30; вперёд — только при отсутствии неудалённых операций раньше новой даты · `Invariant.OpenedOnNotAfterTransactions` |
| INV-30 | `opened_on` лежит в том же диапазоне, что и дата операции: от 2000 года до текущей даты включительно. Счёт, открытый в будущем, не примет ни одной операции (INV-08, INV-09) · `Invariant.OpeningDateInRange` |
| INV-35 | Счёт удаляется только без неудалённых операций, в том числе переводов на него: иначе они выпали бы из лент и балансов. Мягко удалённые операции удалению не мешают · `Invariant.AccountDeletedOnlyWithoutTransactions` |

## Категории

| INV-13 | Дерево категорий имеет ровно два уровня; третий уровень заменён местом (ADR-0005) · `Invariant.TwoCategoryLevels` |
|---|---|
| INV-14 | Подкатегория обязана ссылаться на группу; группа ни на что не ссылается · `Invariant.SubcategoryBelongsToGroup` |
| INV-15 | Вид (доход или расход) и универсальность задаются на первом уровне и наследуются вторым · `Invariant.KindInheritedFromGroup` |
| INV-16 | Подкатегория переносится только в группу того же вида, которая принимает все виды её операций (INV-29) · `Invariant.MoveKeepsKind` |
| INV-17 | Уровень категории не меняется: группа не переносится под другую группу, подкатегория группой не становится · `Invariant.CategoryLevelFixed` |
| INV-18 | У каждой группы ровно один приёмник. Исключение — служебная группа, чья единственная подкатегория неудаляема · `Invariant.GroupHasReceiver` |
| INV-31 | В служебную группу подкатегория не переносится: её единственная подкатегория исключена из отчёта (SEED-06), и переехавшая оказалась бы в отчёте под служебной группой · `Invariant.ServiceGroupClosedToMoves` |
| INV-34 | Группа не удаляется: опустевшая остаётся в справочнике (FR-CAT-11) · `Invariant.GroupNotDeleted` |
| INV-20 | Удаление подкатегории переносит её операции в приёмник той же группы · `Invariant.DeletedSubcategoryGoesToReceiver` |
| INV-23 | Приёмники и служебные категории, включая служебную группу, не удаляются и не переносятся в другую группу: без приёмника группа теряет место для операций удаляемых подкатегорий · `Invariant.ProtectedCategoryStays` |

## Имена

| INV-28 | Имя счёта, категории и места хранится обрезанным и не пусто: необрезанное имя неотличимо в списке от обрезанного · `Invariant.NameTrimmedAndNotEmpty` |
|---|---|
| INV-26 | Имена уникальны среди неудалённых записей: счёт — по всему списку, группа — среди групп своего вида, подкатегория — внутри своей группы, место — по всему справочнику. Сравнение без учёта регистра, окружающие пробелы обрезаются. Нарушение блокирует сохранение; место, набранное в форме операции, не заводится заново, а берётся существующее с тем же именем · `Invariant.NameUnique` |
