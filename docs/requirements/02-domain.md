# Доменная модель и инварианты

Сущности, поля, конвенции именования и правила, которые обязаны соблюдаться всегда. Идентификаторы: `INV-*`.

## Счёт (Account)

| Поле | Тип C# | Тип БД | Описание |
|---|---|---|---|
| `key` | `Guid` | `uuid` / `TEXT` | UUIDv7, генерируется клиентом, первичный ключ |
| `name` | `string` | `text` | Наименование |
| `type` | `enum` | `text` | Наличные или карта. Влияет только на отображение |
| `currency` | `enum` | `char(3)` | RUB, USD или EUR |
| `opening_balance` | `Money` | `numeric(19,2)` / `INTEGER` | Начальный остаток. Валюта берётся из `currency` того же счёта, отдельной колонки не имеет |
| `opened_on` | `DateOnly` | `date` | Дата, с которой действует начальный остаток |
| `excluded_from_totals` | `bool` | `boolean` | «Скрытый»: счёт не входит ни в подытог доступных к тратам, ни в итоги дня, ни в отчёт |
| `is_closed` | `bool` | `boolean` | «Заблокированный»: выведен из употребления, обратимо (FR-ACC-06). Дата блокировки не хранится — ничем не используется |
| `sort_order` | `int` | `integer` | Порядок на главном экране |
| `created_at_utc` | `DateTimeOffset` | `timestamptz` | |
| `updated_at_utc` | `DateTimeOffset` | `timestamptz` | |
| `deleted_at_utc` | `DateTimeOffset?` | `timestamptz` | Надгробие мягкого удаления |
| `synced_at_utc` | `DateTimeOffset?` | `timestamptz` | Подтверждение доставки на сервер |
| `external_id` | `string?` | `text` | Резерв под будущий импорт |

## Категория (Category)

| Поле | Тип C# | Тип БД | Описание |
|---|---|---|---|
| `key` | `Guid` | `uuid` / `TEXT` | UUIDv7; для категорий стартового набора — детерминированный UUIDv5 |
| `parent_key` | `Guid?` | `uuid` | Заполнен только на втором уровне. Им уровень и задаётся: отдельной колонки уровня нет, два источника одного факта разошлись бы, а путь восстановления их не сверяет |
| `kind` | `enum` | `text` | Доход или расход. Задаётся только на первом уровне |
| `accepts_any_kind` | `bool?` | `boolean` | Группа принимает операции обоих видов (ADR-0013). Задаётся только на первом уровне, у подкатегории пусто; после создания не меняется |
| `name` | `string` | `text` | |
| `icon` | `string` | `text` | Устойчивый ключ значка из набора, зашитого в приложение |
| `role` | `enum` | `text` | Обычная, приёмник группы («Прочее») или служебная. Единственный признак, по которому приёмник и неудаляемые категории отличаются от прочих: строкового ключа стартового набора в базе нет, а имя категории пользователь вправе изменить (FR-CAT-03) |
| `exclude_from_reports` | `bool` | `boolean` | Для служебных категорий. От `role` независим: «не показывать в отчёте» и «не удаляется» — разные вопросы |
| `created_at_utc`, `updated_at_utc`, `deleted_at_utc`, `synced_at_utc`, `external_id` | | | Как у счёта |

Ссылка операции на мягко удалённую подкатегорию допустима. В MVP она не возникает: удаление переносит операции по INV-20 в той же транзакции. Появится с обменом — если другое устройство офлайн записало операцию в удалённую подкатегорию. Такая операция показывается с названием удалённой подкатегории, а сама подкатегория в выборе не предлагается; перенос по INV-20 при получении изменений не переигрывается (SYN-18).

## Место (Place)

Справочник мест, с которыми происходят операции: магазины, работодатели, банки, клиники. Одна операция ссылается не более чем на одно место.

| Поле | Тип C# | Тип БД | Описание |
|---|---|---|---|
| `key` | `Guid` | `uuid` / `TEXT` | UUIDv7 |
| `name` | `string` | `text` | |
| `created_at_utc`, `updated_at_utc`, `deleted_at_utc`, `synced_at_utc`, `external_id` | | | Как у счёта |

Ссылка операции на мягко удалённое место допустима. Массовое обнуление ссылок запрещено: история остаётся такой, какой её ввели, а при обмене массовая правка породила бы лишние изменения и конфликты.

## Операция (Transaction)

| Поле | Тип C# | Тип БД | Описание |
|---|---|---|---|
| `key` | `Guid` | `uuid` / `TEXT` | UUIDv7 |
| `kind` | `enum` | `text` | Доход, расход или перевод |
| `source_account_key` | `Guid` | `uuid` | Счёт списания. У расхода и дохода — единственный счёт операции |
| `target_account_key` | `Guid?` | `uuid` | Счёт зачисления, только для перевода |
| `amount` | `Money` | `numeric(19,2)` / `INTEGER` | Всегда положительная. Валюта — валюта счёта списания, отдельной колонки не имеет |
| `target_amount` | `Money?` | `numeric(19,2)` / `INTEGER` | Сумма зачисления в валюте счёта зачисления. Заполнена у любого перевода, а не только у перевода между валютами: при совпадающих валютах равна `amount` (INV-03, INV-05). В форме при одной валюте не запрашивается |
| `category_key` | `Guid?` | `uuid` | Подкатегория |
| `place_key` | `Guid?` | `uuid` | Место. Необязательно, запрещено для перевода |
| `occurred_on` | `DateOnly` | `date` | Календарная дата операции |
| `note` | `string?` | `text` | До 1000 символов |
| `created_at_utc`, `updated_at_utc`, `deleted_at_utc`, `synced_at_utc`, `external_id` | | | Как у счёта |

## Конвенции

- Суффикс `_at_utc` — момент времени, всегда UTC.
- Суффикс `_on` — календарная дата, без времени и часового пояса.
- Все внешние ссылки идут на `key`. Иных идентификаторов у сущностей нет.
- Второй тип в колонке «Тип БД» — хранение в SQLite, где нужного типа нет: ключ лежит текстом в каноническом виде (ADR-0002), денежная колонка — целыми копейками (ADR-0011).

## Операции

| INV-01 | Суммы всегда положительны. Знак определяется видом операции, а не знаком суммы (ADR-0004) · `Invariant.AmountSignComesFromKind` |
|---|---|
| INV-02 | `amount` строго больше нуля · `Invariant.AmountIsPositive` |
| INV-03 | `target_account_key` и `target_amount` заполнены тогда и только тогда, когда вид операции — перевод · `Invariant.TargetOnlyInTransfer` |
| INV-04 | В переводе счёт списания и счёт зачисления не совпадают · `Invariant.TransferAccountsDiffer` |
| INV-05 | Если валюты счетов перевода совпадают, `amount` и `target_amount` равны · `Invariant.SameCurrencyTransferAmountsEqual` |
| INV-06 | Категория обязательна для дохода и расхода, запрещена для перевода · `Invariant.CategoryOnlyInIncomeAndExpense` |
| INV-07 | Категория операции всегда второго уровня · `Invariant.CategoryIsSubcategory` |
| INV-29 | Вид категории совпадает с видом операции — либо группа универсальна и принимает оба вида. Без этого возврат в магазине и кэшбэк записать было бы некуда, кроме доходной статьи, и траты по статье перестали бы быть чистыми · `Invariant.CategoryKindMatchesTransaction` |
| INV-08 | `occurred_on` не раньше `opened_on` обоих задействованных счетов · `Invariant.TransactionNotBeforeAccountOpened` |
| INV-09 | `occurred_on` находится в диапазоне от 2000 года до текущей даты включительно · `Invariant.TransactionDateInRange` |
| INV-10 | Длина заметки не превышает 1000 символов · `Invariant.NoteWithinLimit` |
| INV-22 | Место необязательно для дохода и расхода и запрещено для перевода · `Invariant.PlaceNotInTransfer` |

## Счета

| INV-11 | Валюта счёта не может быть изменена после появления первой операции по нему. Мягко удалённые операции учитываются наравне с живыми: достаточно, чтобы операция по счёту существовала когда-либо · `Invariant.CurrencyFixedOnceUsed` |
|---|---|
| INV-12 | `opened_on` может быть сдвинута назад свободно; вперёд — только при отсутствии операций раньше новой даты · `Invariant.OpenedOnNotAfterTransactions` |
| INV-30 | `opened_on` лежит в том же диапазоне, что и дата операции: от 2000 года до текущей даты включительно. Счёт, открытый в будущем, не примет ни одной операции — она не может быть ни раньше открытия (INV-08), ни позже сегодняшней (INV-09), — и на причину при вводе ничего не укажет · `Invariant.OpeningDateInRange` |

INV-11 не закрывает многоустройственную гонку целиком: другое устройство может держать офлайн неотправленную операцию по счёту, невидимую проверке. Учёт удалённых операций сужает окно до случая, когда операция никогда не доезжала.

## Категории

| INV-13 | Дерево категорий имеет ровно два уровня; третий уровень заменён местом (ADR-0005) · `Invariant.TwoCategoryLevels` |
|---|---|
| INV-14 | Подкатегория обязана ссылаться на группу; группа ни на что не ссылается · `Invariant.SubcategoryBelongsToGroup` |
| INV-15 | Вид (доход или расход) и универсальность задаются на первом уровне и наследуются вторым · `Invariant.KindInheritedFromGroup` |
| INV-16 | Подкатегория переносится только в группу того же вида, которая принимает все виды её операций (INV-29) · `Invariant.MoveKeepsKind` |
| INV-17 | Подкатегория не может быть повышена до группы · `Invariant.CategoryLevelFixed` |
| INV-18 | У каждой группы ровно одна подкатегория «Прочее». Исключение — служебная группа, чья единственная подкатегория неудаляема · `Invariant.GroupHasReceiver` |
| INV-31 | В служебную группу подкатегория не переносится: у служебной группы ровно одна служебная подкатегория (INV-18), а её подкатегория исключена из отчёта (SEED-06) — переехавшая категория оказалась бы в отчёте под служебной группой · `Invariant.ServiceGroupClosedToMoves` |
| INV-34 | Группа не удаляется: опустевшая остаётся в справочнике (FR-CAT-11) · `Invariant.GroupNotDeleted` |

## Правила изменения

| INV-19 | Редактирование операции — замена состояния целиком. Изменению подлежат все поля, включая вид операции · `Invariant.EditReplacesWholeState` |
|---|---|
| INV-25 | Смена вида операции немедленно стирает поля, запрещённые новым видом: при переходе в перевод — категорию и место, при переходе из перевода — счёт зачисления и сумму зачисления. Скрытого состояния не сохраняется: возврат прежнего вида требует ввести поля заново · `Invariant.KindChangeClearsForbiddenFields` |
| INV-20 | Удаление подкатегории переносит её операции в «Прочее» той же группы · `Invariant.DeletedSubcategoryGoesToReceiver` |
| INV-23 | Подкатегории «Прочее» и служебные «Разница» не удаляются и не переносятся в другую группу: без «Прочего» группа теряет приёмник для операций удаляемых подкатегорий · `Invariant.ProtectedCategoryStays` |
| INV-24 | Любая сумма — операции, зачисления, начального остатка — не превышает 999 999 999 999,99 в валюте своего счёта · `Invariant.AmountWithinLimit` |
| INV-32 | Сумма записана не больше чем двумя знаками после запятой, и считаются записанные знаки, а не значение: `1.500` отвергается наравне с `1.505` · `Invariant.AmountInWholeKopecks` |
| INV-33 | Суммы в разных валютах не складываются, не вычитаются и не сравниваются: общей суммы по валютам не существует (ADR-0004) · `Invariant.CurrenciesNeverMixed` |
| INV-21 | Удаление любой сущности выполняется мягко — проставлением `deleted_at_utc` (ADR-0003); повторное удаление метку не сдвигает · `Invariant.DeletionIsSoft` |
| INV-28 | Имя счёта, категории и места хранится обрезанным и не пусто. Необрезанное имя разошлось бы с одинаковым на вид: «Пятёрочка » и «Пятёрочка» — две разные строки в списке и два разных места в подсказках · `Invariant.NameTrimmedAndNotEmpty` |
| INV-26 | Имена уникальны среди неудалённых записей: счёт — по всему списку, группа — среди групп своего вида, подкатегория — внутри своей группы, место — по всему справочнику. Сравнение без учёта регистра, окружающие пробелы обрезаются. Нарушение блокирует сохранение · `Invariant.NameUnique` |
| INV-27 | Заблокированный счёт недопустим в новой операции и при смене счёта в существующей — ни счётом списания, ни счётом зачисления. Уже записанные операции заблокированного счёта правятся и удаляются свободно. Проверка межтабличная, как INV-08 · `Invariant.ClosedAccountNotInNewTransaction` |
