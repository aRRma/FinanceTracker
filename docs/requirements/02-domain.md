# Доменная модель и инварианты

Сущности, поля, конвенции именования и правила, которые обязаны соблюдаться всегда. Идентификаторы: `INV-*`.

## Счёт (Account)

| Поле | Тип C# | Тип БД | Описание |
|---|---|---|---|
| `key` | `Guid` | `uuid` / `TEXT` | UUIDv7, генерируется клиентом, первичный ключ |
| `name` | `string` | `text` | Наименование |
| `type` | `enum` | `text` | Наличные или карта. Влияет только на отображение |
| `currency` | `enum` | `char(3)` | RUB, USD или EUR |
| `opening_balance` | `decimal` | `numeric(19,2)` | Начальный остаток |
| `opened_on` | `DateOnly` | `date` | Дата, с которой действует начальный остаток |
| `excluded_from_totals` | `bool` | `boolean` | «Скрыть из расчётов»: счёт не входит ни в подытог доступных к тратам, ни в итоги дня в ленте |
| `is_closed` | `bool` | `boolean` | «Счёт закрыт»: выведен из употребления, обратимо (FR-ACC-06). Дата закрытия не хранится — ничем не используется |
| `sort_order` | `int` | `integer` | Порядок на главном экране |
| `created_at_utc` | `DateTimeOffset` | `timestamptz` | |
| `updated_at_utc` | `DateTimeOffset` | `timestamptz` | |
| `deleted_at_utc` | `DateTimeOffset?` | `timestamptz` | Надгробие мягкого удаления |
| `synced_at_utc` | `DateTimeOffset?` | `timestamptz` | Подтверждение доставки на сервер |
| `external_id` | `string?` | `text` | Резерв под будущий импорт |

## Категория (Category)

| Поле | Тип C# | Тип БД | Описание |
|---|---|---|---|
| `key` | `Guid` | `uuid` / `TEXT` | UUIDv7; для категорий пресета — детерминированный UUIDv5 |
| `parent_key` | `Guid?` | `uuid` | Заполнен только на втором уровне |
| `level` | `int` | `smallint` | 1 или 2 |
| `kind` | `enum` | `text` | Доход или расход. Задаётся только на первом уровне |
| `name` | `string` | `text` | |
| `icon` | `string` | `text` | Устойчивый ключ значка из набора, зашитого в приложение |
| `exclude_from_reports` | `bool` | `boolean` | Для служебных категорий |
| `created_at_utc`, `updated_at_utc`, `deleted_at_utc`, `synced_at_utc`, `external_id` | | | Как у счёта |

Ссылка операции на мягко удалённую подкатегорию допустима. В MVP она не возникает: удаление переносит операции по INV-20 в той же транзакции. Случай оставлен на будущий обмен, когда одно устройство удалило подкатегорию, а другое офлайн записало в неё операцию. Такая операция отображается с названием удалённой подкатегории, а сама подкатегория в списках выбора не предлагается. Перенос в «Прочее» по INV-20 выполняется только на устройстве, где пользователь подтвердил удаление, и не переигрывается при получении изменений: иначе слой синхронизации исполнял бы доменные правила вопреки SYN-18, и устройства разошлись бы между собой.

## Место (Place)

Справочник мест, с которыми происходят операции: магазины, работодатели, банки, клиники. Одна операция ссылается не более чем на одно место.

| Поле | Тип C# | Тип БД | Описание |
|---|---|---|---|
| `key` | `Guid` | `uuid` / `TEXT` | UUIDv7 |
| `name` | `string` | `text` | |
| `created_at_utc`, `updated_at_utc`, `deleted_at_utc`, `synced_at_utc`, `external_id` | | | Как у счёта |

Ссылка операции на мягко удалённое место допустима и не считается нарушением целостности. Массовое обнуление ссылок при удалении места запрещено: история операций остаётся такой, какой её ввели, а когда появится обмен, массовая правка породила бы сотни строк в очереди отправки и искусственные конфликты слияния.

## Операция (Transaction)

| Поле | Тип C# | Тип БД | Описание |
|---|---|---|---|
| `key` | `Guid` | `uuid` / `TEXT` | UUIDv7 |
| `kind` | `enum` | `text` | Доход, расход или перевод |
| `account_key` | `Guid` | `uuid` | Основной счёт |
| `counter_account_key` | `Guid?` | `uuid` | Счёт назначения, только для перевода |
| `amount` | `decimal` | `numeric(19,2)` | Всегда положительная |
| `counter_amount` | `decimal?` | `numeric(19,2)` | Только для перевода |
| `category_key` | `Guid?` | `uuid` | Подкатегория |
| `place_key` | `Guid?` | `uuid` | Место. Необязательно, запрещено для перевода |
| `occurred_on` | `DateOnly` | `date` | Календарная дата операции |
| `note` | `string?` | `text` | До 1000 символов |
| `created_at_utc`, `updated_at_utc`, `deleted_at_utc`, `synced_at_utc`, `external_id` | | | Как у счёта |

## Конвенции

- Суффикс `_at_utc` — момент времени, всегда UTC.
- Суффикс `_on` — календарная дата, без времени и часового пояса.
- Все внешние ссылки идут на `key`. Иных идентификаторов у сущностей нет.

## Операции

| INV-01 | Суммы всегда положительны. Знак определяется видом операции, а не знаком суммы |
|---|---|
| INV-02 | `amount` строго больше нуля |
| INV-03 | `counter_account_key` и `counter_amount` заполнены тогда и только тогда, когда вид операции — перевод |
| INV-04 | В переводе счета источника и назначения не совпадают |
| INV-05 | Если валюты счетов перевода совпадают, `amount` и `counter_amount` равны |
| INV-06 | Категория обязательна для дохода и расхода, запрещена для перевода |
| INV-07 | Категория операции всегда второго уровня |
| INV-08 | `occurred_on` не раньше `opened_on` обоих задействованных счетов |
| INV-09 | `occurred_on` находится в диапазоне от 2000 года до текущей даты включительно |
| INV-10 | Длина заметки не превышает 1000 символов |
| INV-22 | Место необязательно для дохода и расхода и запрещено для перевода |

## Счета

| INV-11 | Валюта счёта не может быть изменена после появления первой операции по нему. Мягко удалённые операции учитываются наравне с живыми: достаточно, чтобы операция по счёту существовала когда-либо |
|---|---|
| INV-12 | `opened_on` может быть сдвинута назад свободно; вперёд — только при отсутствии операций раньше новой даты |

INV-11 не закрывает многоустройственную гонку целиком: другое устройство может держать офлайн неотправленную операцию по счёту, невидимую проверке. Учёт удалённых операций сужает окно до случая, когда операция никогда не доезжала.

## Категории

| INV-13 | Дерево категорий имеет ровно два уровня |
|---|---|
| INV-14 | Подкатегория обязана ссылаться на группу; группа ни на что не ссылается |
| INV-15 | Вид (доход или расход) задаётся на первом уровне и наследуется вторым |
| INV-16 | Подкатегория может быть перенесена в другую группу того же вида |
| INV-17 | Подкатегория не может быть повышена до группы |
| INV-18 | У каждой группы существует подкатегория «Прочее». Исключение — служебные группы, чья единственная подкатегория неудаляема |

## Правила изменения

| INV-19 | Редактирование операции — замена состояния целиком. Изменению подлежат все поля, включая вид операции |
| INV-25 | Смена вида операции немедленно стирает поля, запрещённые новым видом: при переходе в перевод — категорию и место, при переходе из перевода — счёт назначения и вторую сумму. Скрытого состояния не сохраняется: возврат прежнего вида требует ввести поля заново |
|---|---|
| INV-20 | Удаление подкатегории переносит её операции в «Прочее» той же группы |
| INV-23 | Подкатегории «Прочее» и служебные «Разница» не удаляются и не переносятся в другую группу: без «Прочего» группа теряет приёмник для операций удаляемых подкатегорий |
| INV-24 | Сумма операции не превышает 999 999 999 999,99 в валюте счёта |
| INV-21 | Удаление любой сущности выполняется мягко — проставлением `deleted_at_utc` |
| INV-26 | Имена уникальны среди неудалённых записей: счёт — по всему списку, группа — среди групп своего вида, подкатегория — внутри своей группы, место — по всему справочнику. Сравнение без учёта регистра, окружающие пробелы обрезаются. Нарушение блокирует сохранение |
| INV-27 | Закрытый счёт недопустим в новой операции и при смене счёта в существующей — ни основным, ни счётом назначения. Уже записанные операции закрытого счёта правятся и удаляются свободно. Проверка межтабличная, доменным сервисом, как INV-08 |
