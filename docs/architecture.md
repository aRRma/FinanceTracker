# Архитектурные решения и стек

Состав проектов, организация прикладного слоя, работа с данными, выбор технологий. Идентификаторы: `TECH-*`.

## Состав проектов

В MVP создаются четыре проекта:

| Проект | Содержимое | Зависимости |
|---|---|---|
| `Finance.Domain` | Сущности, типы-значения, инварианты, доменные сервисы | Отсутствуют |
| `Finance.Application` | Слайсы функций: команда, обработчик, запросы, модель представления. Инфраструктура (доступ к данным, журналирование, уведомления) — папкой внутри | Domain |
| `Finance.App` | Приложение MAUI: страницы, навигация, ресурсы темы | Domain, Application |
| `Finance.Domain.Tests` | Тесты инвариантов и обработчиков | Domain, Application |

Обработчики, запросы и модели представления вынесены из проекта MAUI намеренно: обычная библиотека тестируется обычным xUnit, без эмулятора и без сборки под Android. В `Finance.App` остаётся только то, что без MAUI не существует.

Инфраструктура отдельным проектом не выделяется: у неё один потребитель, а шов, за которым ничего не меняется, добавляет ходы и ничего не даёт. Вынести её позже не ломает написанного.

Отложено до появления обмена с сервером:

| Проект | Содержимое | Зависимости |
|---|---|---|
| `Finance.Contracts` | Объекты передачи данных протокола, перечисления | Отсутствуют |
| `Finance.Server` | Сервер синхронизации | Contracts |

`Finance.Contracts` не будет ссылаться на `Finance.Domain`: сервер не исполняет доменную логику и не должен получать её транзитивно.

## Организация прикладного слоя

Код режется по функциям, а не по техническим слоям: `Features/Transactions/Add`, `Features/Transactions/Edit`, `Features/Accounts/Reorder`, `Features/Balances`, `Features/Sync`. Слайс содержит команду, обработчик, модель представления и страницу.

Слайсы не ссылаются друг на друга. Запрос, потребовавшийся второму слайсу, переносится в общую инфраструктуру.

## Работа с данными

- Доступ через фабрику контекстов, отдельный контекст на операцию.
- Пишущий путь идёт через доменные типы, читающий — напрямую в плоские модели с проекцией на стороне базы.
- Простые запросы выполняются без обёрток; составные скрываются за именованными методами.
- Доменные сущности не передаются между контекстами.

## Команды

- Обработчики вызываются моделями представления напрямую, через интерфейсы. Посредник для диспетчеризации не применяется.
- Граница транзакции задаётся декоратором вокруг команд. Декоратор учитывает отсутствие вложенных транзакций в SQLite.
- Наполнение очереди отправки, проставление `updated_at_utc` и публикация событий изменения выполняются при сохранении.
- Засев пресета выполняется в обход автоматической установки меток времени.
- События публикуются после фиксации транзакции, несут тип изменившейся сущности и доставляются в поток интерфейса.

## Валидация и ошибки

- Проверки формы ввода реализуются валидатором команды.
- Правила, требующие знания домена, реализуются в доменных типах.
- Нарушение инварианта выражается доменным исключением специального типа и обрабатывается глобально.
- Межтабличные инварианты реализуются доменным сервисом, принимающим операцию и связанные счета.

## Создание и восстановление сущностей

Конструкторы доменных типов закрыты. Создание выполняется фабричным методом с полной проверкой. Восстановление из хранилища идёт отдельным путём без проверок. Путь восстановления публичный: ограничивать его видимость не нужно. Его XML-комментарий обязан прямо говорить, что метод не проверяет инварианты и предназначен только для чтения из хранилища.

## Клиент

| Компонент | Выбор |
|---|---|
| Платформа | .NET 10, MAUI, Android |
| Навигация | Shell с типизированной обёрткой поверх маршрутов |
| Модели представления | CommunityToolkit.Mvvm |
| Доступ к данным | EF Core с предкомпилированной моделью |
| Хранилище | SQLite в режиме журналирования с упреждающей записью |
| Сеть | HttpClient через фабрику с обработчиком повторов |
| Сериализация | System.Text.Json |

## Сервер

| Компонент | Выбор |
|---|---|
| Платформа | .NET 10, ASP.NET Core Minimal API |
| Хранилище | PostgreSQL, локально в контейнере |
| Доступ к данным | EF Core с миграциями |
| Аутентификация | Статический токен в конфигурации |

## Особенности реализации

| TECH-01 | Идентификаторы хранятся в SQLite текстом в каноническом представлении. Двоичное представление .NET имеет платформозависимый порядок байтов и ломает сортировку ленты и локальность вставок (ADR-0002) |
|---|---|
| TECH-02 | Предкомпилированная модель перегенерируется при каждом изменении сущностей. Шаг встраивается в сборку |
| TECH-03 | Корректность работы проверяется на релизной сборке: отсечение неиспользуемого кода влияет на механизмы, использующие отражение |
| TECH-04 | При разработке эмулятор обращается к хосту по служебному адресу; для незашифрованного соединения требуется отладочная конфигурация сетевой безопасности |
| TECH-05 | В эксплуатации перед сервисом устанавливается обратный прокси с автоматическим получением сертификата |
