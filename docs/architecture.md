# Архитектурные решения и стек

Состав проектов, организация прикладного слоя, работа с данными, выбор технологий. Идентификаторы: `TECH-*`.

## Состав проектов

В MVP создаются шесть проектов:

| Проект | Содержимое | Целевой фреймворк | Зависимости |
|---|---|---|---|
| `Finance.Domain` | Сущности, типы-значения, инварианты, доменные сервисы | `net10.0` | Отсутствуют |
| `Finance.Application` | Слайсы функций: команда, обработчик, запросы, модель представления. Инфраструктура (доступ к данным, журналирование, уведомления) — папкой внутри | `net10.0` | Domain |
| `Finance.App` | Приложение MAUI: страницы, навигация, ресурсы темы | `net10.0-android`, `SupportedOSPlatformVersion` = 36 (SYS-01) | Domain, Application |
| `Finance.Domain.Tests` | Тесты доменных правил: срабатывание каждого и пропуск корректного значения | `net10.0` | Domain, Application |
| `Finance.Application.Tests` | Тесты обработчиков, запросов и моделей представления на настоящей базе SQLite во временной папке | `net10.0` | Domain, Application |
| `Finance.Docs.Tests` | Проверки стартового набора и документации, переехавшие из `tools/` | `net10.0` | Domain и Application — ради той же реализации UUIDv5 и того же разбора стартового набора, которыми пользуется инициализация базы. Документы и данные читает как файлы |

Обработчики, запросы и модели представления вынесены из проекта MAUI намеренно: обычная библиотека тестируется обычным xUnit, без эмулятора и без сборки под Android. В `Finance.App` остаётся только то, что без MAUI не существует.

Инфраструктура отдельным проектом не выделяется: у неё один потребитель, а шов, за которым ничего не меняется, добавляет ходы и ничего не даёт. Вынести её позже не ломает написанного.

Отложено до появления обмена с сервером:

| Проект | Содержимое | Зависимости |
|---|---|---|
| `Finance.Contracts` | Объекты передачи данных протокола, перечисления | Отсутствуют |
| `Finance.Server` | Сервер синхронизации | Contracts |

`Finance.Contracts` не будет ссылаться на `Finance.Domain`: сервер не исполняет доменную логику и не должен получать её транзитивно.

## Организация прикладного слоя

Код режется по функциям, а не по техническим слоям: `Features/Transactions/Card`, `Features/Accounts/Card`, `Features/Accounts/Catalog`, `Features/Balances`, `Features/Feed`, `Features/Sync`. Слайс содержит команду, обработчик, запросы и модель представления; страница живёт в `Finance.App`. Запись и правка одной сущности — один слайс `Card`: экран у них один, а отличает их только заполненный ключ.

Слайсы не ссылаются друг на друга. Запрос, потребовавшийся второму слайсу, переносится в общую инфраструктуру.

## Работа с данными

- Доступ через фабрику контекстов, отдельный контекст на операцию.
- Пишущий путь идёт через доменные типы, читающий — напрямую в плоские модели с проекцией на стороне базы.
- Простые запросы выполняются без обёрток; составные скрываются за именованными методами.
- Доменные сущности не передаются между контекстами.

## Команды

- Обработчики вызываются моделями представления напрямую, через интерфейсы. Посредник для диспетчеризации не применяется.
- Граница транзакции задаётся типом `UnitOfWork`: обработчик передаёт ему тело команды, а не открывает транзакцию сам. Вложенности нет — её нет и в SQLite: команда получает свой контекст и свою транзакцию, а обработчики друг друга не вызывают.
- Наполнение очереди отправки, проставление `updated_at_utc` и публикация событий изменения выполняются при сохранении.
- Инициализация базы выполняется в обход автоматической установки меток времени.
- События публикуются после фиксации транзакции, несут тип изменившейся сущности и доставляются в поток интерфейса.

## Валидация и ошибки

- Проверки формы ввода — незаполненное поле, недобранная сумма — живут в модели представления: она же показывает сообщение и подводит к нему экран.
- Правила, требующие знания домена, реализуются в доменных типах.
- Нарушение инварианта выражается доменным исключением специального типа. Ловит его модель представления карточки и показывает текст правила на самом экране: глобальный перехват сказал бы о нарушении, но не показал бы, какое поле править.
- Межтабличные инварианты реализуются доменным сервисом, принимающим операцию и связанные счета.

## Создание и восстановление сущностей

Конструкторы доменных типов закрыты. Создание выполняется фабричным методом с полной проверкой. Восстановление из хранилища идёт отдельным путём без проверок. Путь восстановления публичный: ограничивать его видимость не нужно. Его XML-комментарий обязан прямо говорить, что метод не проверяет инварианты и предназначен только для чтения из хранилища.

## Особенности реализации

| TECH-01 | Идентификаторы хранятся в SQLite текстом в каноническом представлении. Двоичное представление .NET имеет платформозависимый порядок байтов и ломает сортировку ленты и локальность вставок (ADR-0002) |
|---|---|
| TECH-02 | Предкомпилированная модель не применяется: EF отказывается её собирать, пока у таблиц есть глобальный фильтр мягкого удаления, а фильтр важнее — без него забытое в одном запросе отсечение показало бы удалённые записи, и заметили бы это не сразу. Модель из пяти таблиц строится при первом обращении к базе |
| TECH-03 | Корректность работы проверяется на релизной сборке: отсечение неиспользуемого кода влияет на механизмы, использующие отражение |
| TECH-04 | При разработке эмулятор обращается к хосту по служебному адресу; для незашифрованного соединения требуется отладочная конфигурация сетевой безопасности |
| TECH-05 | В эксплуатации перед сервисом устанавливается обратный прокси с автоматическим получением сертификата |
| TECH-06 | Тема оформления и версия приложения приходят в прикладной слой снаружи, параметрами сборки служб: что такое тёмное оформление окна и где лежит манифест, знает только MAUI. Тема применяется через тот же переход в поток интерфейса, что и оповещение об изменении данных — подготовка приложения идёт в фоновом потоке |
| TECH-07 | Номер схемы базы для экрана «О программе» — число накатанных миграций, прочитанное у самой базы. Отдельный счётчик версии схемы не заводится: он разошёлся бы с фактическим состоянием базы при первой же забытой правке |
