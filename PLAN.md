# План реализации

## Этап 0 · Доменное ядро

- [ ] Решение из пяти проектов, зависимости по [CLAUDE.md](CLAUDE.md)
- [ ] Тип денег: валюта в типе, сложение разных валют бросает исключение
- [ ] Сущности с закрытыми конструкторами: фабричный `Create` с проверками, отдельный путь восстановления без проверок
- [ ] Инварианты INV-01 … INV-23
- [ ] Доменный сервис межтабличных проверок (дата операции против дат открытия обоих счетов)
- [ ] Тесты: на каждый инвариант срабатывание и пропуск корректного значения
- [ ] Тест валидации [data/preset.json](data/preset.json): пересчёт UUIDv5 из ключей, значки из [data/icons.json](data/icons.json), «Прочее» в каждой неслужебной группе (INV-18), заведомо давняя метка засева (SEED-03). После этого [tools/validate_preset.py](tools/validate_preset.py) удаляется

Готово, когда доменный проект не имеет внешних зависимостей и каждый инвариант покрыт тестом.

## Этап 1 · Локальное приложение

- [ ] Схема, миграции, резервная копия через `VACUUM INTO` перед накатом
- [ ] Контекст через фабрику, предкомпилированная модель, режим WAL
- [ ] Переопределение сохранения: `updated_at_utc`, очередь отправки, события изменения
- [ ] Засев пресета из [data/preset.json](data/preset.json) с фиксированной меткой времени
- [ ] Слайсы: создание, правка, удаление операции; счета; категории; места; порядок счетов
- [ ] Запросы балансов и ленты (`UNION ALL`, индексы по SYN и NFR-03, NFR-04)
- [ ] Экраны по [docs/ui/mockups.html](docs/ui/mockups.html)
- [ ] Темы: системная, светлая, тёмная; все цвета через токены (FR-SET-03, NFR-23…25); эталон палитр — переключатель темы в [docs/ui/mockups.html](docs/ui/mockups.html)
- [ ] Навигация Shell с типизированной обёрткой

Готово, когда приложение стоит на телефоне и используется по назначению.

## Этап 2 · Синхронизация

- [ ] DTO протокола и номер версии
- [ ] Сервер: схема без внешних ключей, счётчик изменений, два эндпоинта, статический токен
- [ ] Клиент: пачка в топологическом порядке, обработка списка принятых ключей, продвижение курсора
- [ ] Применение полученного с буферизацией и упорядочиванием
- [ ] Слияние по SYN-14 и SYN-15
- [ ] Экран состояния обмена

Готово, когда полная выгрузка данных первого этапа проходит без потерь и повторный запуск не создаёт дублей.

## Этап 3 · Второе устройство

- [ ] Правка одной операции на двух устройствах офлайн
- [ ] Удаление против правки
- [ ] Удалённая категория пресета при установке на новое устройство
- [ ] Переименованная категория пресета при установке на новое устройство
- [ ] Обрыв связи посреди отправки пачки
- [ ] Часы одного устройства сдвинуты вперёд

Каждый сценарий оформляется тестом. Готово, когда результат детерминирован и совпадает на обоих устройствах.

## Этап 4 · Развитие

Порядок по ценности: отчёт о расходах по категориям · выгрузка в файл · автозапуск синхронизации · внешняя аутентификация · поиск и фильтры · чистка надгробий и полная пересинхронизация · сверка контрольной суммой · блокировка приложения.
