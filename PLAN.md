# План реализации

Границы MVP: одно устройство одного пользователя, без сети. Обмен с сервером отложен целиком — см. [docs/requirements/06-sync-deferred.md](docs/requirements/06-sync-deferred.md).

## Этап 0 · Доменное ядро

- [ ] Решение из четырёх проектов: `Finance.Domain`, `Finance.Application`, `Finance.App`, `Finance.Domain.Tests`. Зависимости по [CLAUDE.md](CLAUDE.md), Android 16 (API 36)
- [ ] Тип денег: валюта в типе, сложение разных валют бросает исключение
- [ ] Сущности с закрытыми конструкторами: фабричный `Create` с проверками, отдельный публичный путь восстановления без проверок и с предупреждающим комментарием
- [ ] Инварианты INV-01 … INV-26 — все существующие, диапазон сверять с [docs/requirements/02-domain.md](docs/requirements/02-domain.md), а не с этим списком
- [ ] Доменный сервис межтабличных проверок (дата операции против дат открытия обоих счетов)
- [ ] Тесты: на каждый инвариант срабатывание и пропуск корректного значения
- [ ] Проверки документации и пресета переезжают в `Finance.Docs.Tests`, оба скрипта из `tools/` удаляются одновременно

Готово, когда доменный проект не имеет внешних зависимостей и каждый инвариант покрыт тестом.

## Этап 1 · Локальное приложение

- [ ] Схема, миграции, резервная копия через `VACUUM INTO` перед накатом (NFR-06)
- [ ] Контекст через фабрику, предкомпилированная модель, режим WAL
- [ ] Переопределение сохранения: `updated_at_utc` и события изменения. Очередь отправки — место оставлено, кода нет
- [ ] Засев пресета из [data/preset.json](data/preset.json) с фиксированной меткой времени
- [ ] Слайсы: создание, правка, удаление операции; счета; категории; места; порядок счетов
- [ ] Запросы балансов и ленты (`UNION ALL`, индексы по NFR-03 и NFR-04)
- [ ] Экраны по [docs/ui/mockups.html](docs/ui/mockups.html)
- [ ] Темы: системная, светлая, тёмная; все цвета через токены (FR-SET-03, NFR-23…25); эталон палитр — переключатель темы в [docs/ui/mockups.html](docs/ui/mockups.html)
- [ ] Навигация Shell с типизированной обёрткой, четыре вкладки: балансы, операции, отчёт, ещё

Готово, когда приложение стоит на телефоне и используется по назначению.

## Этап 2 · Отчёт

- [ ] Запросы агрегации по группам и подкатегориям за месяц, на стороне базы (NFR-02)
- [ ] Три уровня: группы, подкатегории, операции (FR-RPT-03…05)
- [ ] Переключатель расходов и доходов, переключение месяца (FR-RPT-01, FR-RPT-02)
- [ ] Исключения: переводы, счета со «скрыть из расчётов», категории вне отчётов, валюты кроме рубля (FR-RPT-06…08)
- [ ] Пустое состояние месяца без операций (FR-RPT-09)

Готово, когда по отчёту видно, куда ушли деньги за месяц, и цифры сходятся с лентой.

## Этап 3 · Развитие

Порядок по ценности: выгрузка в файл · синхронизация между устройствами (этапы обмена, сервера и слияния разворачиваются из [docs/requirements/06-sync-deferred.md](docs/requirements/06-sync-deferred.md)) · поиск и фильтры · внешняя аутентификация · блокировка приложения.
